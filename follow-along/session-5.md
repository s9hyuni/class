# 5회차: 내 구글 시트와 GAS 웹 앱

- **시작 상태**: 4회차를 끝낸 `C:\ai-class\tumble-dashboard`에서 이어 합니다. 화면이 내 NestJS 서버(`http://127.0.0.1:3000`)의 값으로 "조회 정상"입니다. 4회차를 못 끝냈으면 아래 "시작 전에"의 안내대로 `milestone-4` 브랜치를 새 폴더에 받습니다.
- **끝나면 되는 것**: 내 Google 시트의 기록을 읽는 Google Apps Script(GAS) 웹 앱이 생기고, 화면이 그 웹 앱의 값으로 4회차와 같은 배치로 나옵니다. 생산 기록 보기와 출고 기록 보기도 됩니다. 4회차의 내 서버(`backend`)는 켜지 않아도 되고, 화면 코드는 고치지 않습니다.
- **준비물**: 개인 Google 계정으로 로그인한 Chrome, 인터넷, 명령을 칠 PowerShell 창, 화면 서버를 켜 둘 PowerShell 창. 회사·학교 Google 계정은 관리자 정책으로 Apps Script API나 "로그인 없이 누구나" 웹 앱 배포가 막혀 있을 수 있습니다. 막히면 개인 계정으로 처음부터 합니다.

| 번호 | 하는 일 |
|---|---|
| 5-1 | Apps Script API 켜기 (직접 하기) |
| 5-2 ~ 5-7 | Google 명령(`npm.cmd run gas:…`) 만들기 |
| 5-8 | Google 로그인 (직접 하기) |
| 5-9 ~ 5-22 | Google에서 돌아갈 코드(`gas` 폴더) 만들기 |
| 5-23 ~ 5-28 | 올리기, 권한 승인과 실습 시트, 배포, 화면 확인 (직접 하기) |
| 5-29 ~ 5-31 | 기록 조회를 더하고 다시 배포 |

## 시작 전에 (프롬프트 없이 직접 합니다)

### 이번 회차 문서 받기

**4회차를 끝냈으면: 문서만 받습니다.** PowerShell 창에서 첫 줄부터 칩니다.

```powershell
cd C:\ai-class\tumble-dashboard
git fetch origin
git checkout origin/milestone-4 -- AGENTS.md docs/guide
```

- 확인: 파일 탐색기나 AI 도구의 파일 목록에서 `docs\guide`의 가장 큰 번호가 `session-5.md`입니다.
- 내 코드는 바뀌지 않습니다. AI 도구에 파일 변경 표시가 생겨도 그대로 둡니다. 커밋하지 않습니다.
- 첫 줄이나 둘째 줄에서 빨간 오류가 나오면 다음으로 가지 말고 강사에게 알립니다.
- 받는 두 줄(`git fetch`, `git checkout`)은 늘 함께 칩니다. `git fetch`를 빼면 오류 없이 옛 문서를 받습니다.
- `docs\guide` 안의 파일을 고치면 받을 때 경고 없이 저장소 판으로 덮입니다. 내 메모는 이 폴더 밖에 둡니다.
- 줄 끝의 `-- AGENTS.md docs/guide`를 빠뜨려 화면에 `detached HEAD`가 보이면 `git switch -`를 치고 강사에게 알립니다. `error:`로 끝나고 멈췄다면 아무것도 바뀌지 않은 것이니 명령을 다시 복사해 칩니다.
- 회차를 진행하는 중에 강사가 문서를 고쳤다고 알리면 이 명령을 한 번 더 칩니다. 내 코드는 그대로입니다.

**4회차를 못 끝냈으면: 완료 브랜치를 새 폴더에 받습니다.** 이 브랜치에 문서도 함께 들어 있습니다.

1. 켜 둔 서버를 모두 그 창에서 Ctrl+C로 끄고, 그 창들과 AI 도구를 닫습니다. 폴더를 쓰는 프로그램이 있으면 이름이 바뀌지 않을 수 있습니다.
2. PowerShell 창을 새로 열고 칩니다.

```powershell
cd C:\ai-class
Rename-Item tumble-dashboard tumble-dashboard-before-session-5
git clone -b milestone-4 https://github.com/startup-life/aiops-dashboard-student.git tumble-dashboard
```

빨간 오류가 나오면 다음으로 가지 말고 강사에게 알립니다.

3. GitHub 로그인 창이 뜨면 초대받은 계정으로 로그인합니다.
4. [공통 안내](README.md)의 "4회차 이후 브랜치"대로 `backend` 폴더의 패키지와 빌드 결과를 만듭니다.
5. AI 도구로 새 `tumble-dashboard` 폴더를 엽니다. 내가 만든 코드는 `tumble-dashboard-before-session-5`에 남습니다.

### 준비

1. AI 도구로 `C:\ai-class\tumble-dashboard` 폴더를 엽니다.
2. 4회차 서버(`backend`)를 켜 둔 창이 있으면 Ctrl+C로 꺼도 됩니다. 이번 회차에는 쓰지 않습니다.
3. Chrome에서 수업에 쓸 개인 Google 계정으로 로그인해 둡니다. 이 회차의 Google 작업은 모두 이 계정 하나로 합니다.

## 진행 방법

- 프롬프트 상자 하나를 통째로 복사해 AI 도구 대화창에 붙여 넣습니다. 앞 번호가 끝난 뒤에 다음 번호를 보냅니다.
- AI 도구가 바꾸려는 파일이나 실행할 명령을 물어보면 훑어보고 승인합니다. 도구마다 다를 수 있어서 묻지 않아도 문제가 아닙니다. 단 `icacls`, `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램을 바꾸는 명령은 승인하지 말고 강사에게 알립니다. `public\config.js`, `.clasp.json`, `.env`를 열겠다고 하거나 `npm.cmd run gas:`, `npm.cmd start`, `git`을 실행하겠다고 하면 승인하지 말고 "이건 제가 직접 합니다"라고 보냅니다.
- 제목에 (직접 하기)가 붙은 단계와 "직접 하기"에 적힌 일은 AI 도구에 맡기지 않고 내가 합니다. 명령은 PowerShell 창에 직접 치고, Google 로그인과 권한 승인도 내가 브라우저에서 합니다. 창을 새로 열었으면 먼저 `cd C:\ai-class\tumble-dashboard`를 칩니다.
- 5-9부터 만드는 `gas` 폴더의 코드는 내 컴퓨터가 아니라 Google에서 실행됩니다. 5-24에서 Google에 올리기 전까지는 파일 안의 글자를 찾는 것까지만 확인합니다.
- 파일 안의 글자를 찾을 때는 PowerShell 창에서 `notepad gas\Core.gs`처럼 메모장으로 열고 Ctrl+F를 누릅니다. 확인했으면 고치지 말고 닫습니다.
- 화면 서버는 4회차와 같이 내가 직접 `npm.cmd start`로 켜고 http://127.0.0.1:4173 을 엽니다. 이번 회차에는 화면 코드가 바뀌지 않으니 브라우저만 새로고침합니다.
- 꼭 지킬 것: 웹 앱 주소를 아는 사람은 누구나 내 시트의 기록을 읽을 수 있습니다. 배포 주소와 그 주소가 든 `public\config.js`는 다른 사람에게 보내지 않고, 채팅·화면 공유·문서에 옮기지 않습니다. AI 도구 대화창에도 붙여 넣지 않습니다.

## 5-1. Apps Script API 켜기 (직접 하기)

1. Chrome에서 개인 Google 계정으로 https://script.google.com/home/usersettings 를 엽니다.
2. "Google Apps Script API"를 사용(켜짐)으로 바꿉니다.

- 확인: 설정이 "사용"으로 보입니다.
- 이 설정이 꺼져 있으면 뒤의 Google 명령이 `User has not enabled the Apps Script API`로 실패합니다. 그 문구가 나오면 이 단계를 다시 하고 1~2분 뒤 같은 명령을 다시 칩니다.

## 5-8. Google 로그인 (직접 하기)

1. PowerShell 창에서 `npm.cmd run gas:login`을 칩니다. 처음에는 clasp를 내려받느라 시간이 조금 걸립니다.

3. 끝났다는 글이 나온 브라우저 탭은 닫습니다.

- 확인: PowerShell 창에 로그인됐다는 문구가 나오고 명령이 끝납니다.

## 5-9. 웹 앱 설정 파일

이제 Google에서 돌아갈 코드를 `gas` 폴더에 씁니다. 파일 다섯 개를 여러 번에 나눠 만듭니다.

- 확인: 파일 탐색기나 AI 도구의 파일 목록에 `gas\appsscript.json`이 생기고, 안에 `ANYONE_ANONYMOUS`와 `USER_DEPLOYING`이 있습니다. 이 두 값이 다르면 화면이 로그인 없이 웹 앱을 부르지 못합니다.
- 권한 세 가지(시트, 외부 서비스 연결, 트리거)를 지금 적어 두면 5-25에서 한 번에 승인합니다. 뒤의 두 권한은 6회차에 씁니다.

## 참고

- **Google 쪽 코드를 고친 뒤에는** `npm.cmd run gas:push`와 `npm.cmd run gas:redeploy`를 차례로 칩니다. 둘 다 해야 웹 앱이 바뀌고, 주소는 그대로입니다.
- **로그인이 만료되면** 명령에서 `invalid_grant`가 나옵니다. `npm.cmd run gas:login`을 다시 치고 같은 명령을 다시 칩니다.
- **강사 API(1단계)나 내 서버(2단계)로 돌아갈 때**는 앱 폴더 맨 위 `README.md`의 단계별 값 표에 있는 값으로 `public\config.js`의 `apiBaseUrl`과 `timeoutMs`를 바꿉니다.
- **다시 내 GAS 웹 앱(3단계)으로 올 때는 `gas:deploy`를 다시 하지 않습니다.** 주소가 없는 `config.js`에서 `gas:deploy`를 하면 배포가 하나 더 생겨 주소가 바뀝니다. 메모해 둔 `/exec` 주소를 `apiBaseUrl`에 직접 넣고 `timeoutMs`를 `15000`으로 바꿉니다.
- 실습 시트를 새로 만들고 싶으면 편집기에서 `createTrainingSpreadsheet`를 다시 실행합니다. 새 시트가 생기고 웹 앱은 새 시트를 읽습니다. 이전 시트는 그대로 남습니다.
