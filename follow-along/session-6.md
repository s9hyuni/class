# 6회차: Discord 알림, 기록 처리, 트리거

- **시작 상태**: 5회차를 끝낸 `C:\ai-class\tumble-dashboard`에서 이어 합니다(완료 브랜치 `milestone-5`와 같은 출발점). 내 GAS 웹 앱이 배포돼 있고, 화면은 내 Google 시트 값으로 "조회 정상"이며 기록 보기도 됩니다. 5회차를 못 끝냈으면 아래 "시작 전에"의 안내대로 `milestone-5` 브랜치를 새 폴더에 받습니다.
- **끝나면 되는 것**
  - 내 Discord 시험 채널로 알림이 가고, 화면의 운영 상태 알림 카드에 "전송 성공"이 뜹니다.
  - GAS 편집기에서 함수를 실행하거나 시트를 직접 고쳐 기록을 더하고 처리하면 화면 수량이 바뀝니다.
  - 자동 실행(트리거) 두 개가 동작합니다. 하나는 시트를 고치면 바로 처리하고, 하나는 1분마다 늦은 기록을 알립니다. 실습이 끝나면 지웁니다.
- **준비물**: 5회차에 쓴 개인 Google 계정으로 로그인한 Chrome, Discord 계정(Chrome에서 https://discord.com 으로 써도 됩니다), 명령을 칠 PowerShell 창, 화면 서버를 켜 둘 PowerShell 창(이하 화면 창)

- 내 코드는 바뀌지 않습니다. AI 도구에 파일 변경 표시가 생겨도 그대로 둡니다. 커밋하지 않습니다.
- 첫 줄이나 둘째 줄에서 빨간 오류가 나오면 다음으로 가지 말고 강사에게 알립니다.
- 받는 두 줄(`git fetch`, `git checkout`)은 늘 함께 칩니다. `git fetch`를 빼면 오류 없이 옛 문서를 받습니다.

- 회차를 진행하는 중에 강사가 문서를 고쳤다고 알리면 이 명령을 한 번 더 칩니다. 내 코드는 그대로입니다.

빨간 오류가 나오면 다음으로 가지 말고 강사에게 알립니다.

6. Google 프로젝트를 만든 적이 없으면(옛 폴더에 `.clasp.json`이 없으면) 4번 복사 대신, 5회차 파일에서 프롬프트 없는 직접 하기 단계만 차례로 합니다. 5-1(Apps Script API 켜기), 5-8(`gas:login`), 5-23(`gas:create`), 5-24(`gas:push`), 5-25(첫 권한 승인과 실습 시트 만들기), 5-26(`gas:deploy`), 5-27(`gas:open`), 5-28(화면 확인)입니다. 5-28의 마지막 확인(생산 기록 보기의 "서버가 알린 이유")은 건너뜁니다. 받은 코드에는 기록 조회가 들어 있어 표가 바로 나옵니다. 5-29~5-31은 하지 않습니다.

### 수업 날 새 실습 시트 만들기

화면은 "오늘" 기록만 셉니다. 5회차에 만든 시트의 시드 기록은 그날 날짜라서 오늘 화면에는 기록이 없게 나옵니다. 오늘 날짜로 시드 기록이 든 새 시트를 만듭니다. 웹 앱은 다시 배포하지 않아도 새 시트를 읽습니다.

- 직접 하기: PowerShell 창에서 `cd C:\ai-class\tumble-dashboard`를 치고 `npm.cmd run gas:editor`로 편집기를 엽니다.
- 직접 하기: Chrome에 열린 편집기 오른쪽 위 계정이 5회차에 쓴 개인 Google 계정인지 봅니다. 왼쪽 파일 목록에서 `Setup.gs`를 누르고, 위쪽 함수 선택에서 `createTrainingSpreadsheet`를 골라 "실행"을 누릅니다.
- 직접 하기: 화면 창에서 `cd C:\ai-class\tumble-dashboard`를 치고 `npm.cmd start`로 화면 서버를 켠 뒤 Chrome에서 http://127.0.0.1:4173 을 엽니다.
- 확인: 실행 로그에 `새 실습 시트: https://docs.google.com/spreadsheets/…`가 나옵니다. 10~15초 안에 화면이 "생산 100개 · 목표 120개", "출고 75개 · 목표 100개"이고 "조회 정상"입니다.
- 이 시트는 이번 회차 내내 씁니다. 실행 로그의 주소를 Ctrl+클릭해 새 탭으로 열어 둡니다. 주소는 다른 곳에 옮기지 않습니다.

## 진행 방법

- **꼭 지킬 것**: Discord 웹훅 주소를 아는 사람은 누구나 내 채널에 글을 보낼 수 있습니다. 주소는 GAS 스크립트 속성에만 넣고 채팅, 화면 공유, 캡처, 코드, 시트에 옮기지 않습니다.
- 차례: 6-1~6-9 Discord 시험 알림, 6-10~6-19 기록 더하기와 처리하기, 6-20~6-25 트리거, 6-26 발표 준비, 6-27 트리거 지우기.
- AI 도구가 바꾸려는 파일이나 실행할 명령을 물어보면 훑어보고 승인합니다. 도구마다 다를 수 있어서 묻지 않아도 문제가 아닙니다. 단 `icacls`, `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램을 바꾸는 명령은 승인하지 말고 강사에게 알립니다. `public\config.js`, `.clasp.json`, `.env`를 열겠다고 하거나 `npm.cmd run gas:`, `npm.cmd start`, `git`을 실행하겠다고 하면 승인하지 말고 "이건 제가 직접 합니다"라고 보냅니다.
- 이번 회차 프롬프트는 Google 쪽 코드에 함수를 하나씩 더합니다. AI 도구는 내 컴퓨터의 파일만 고칩니다. Google에 반영하려면 내가 PowerShell 창에서 `npm.cmd run gas:push`로 올려야 합니다. 창을 새로 열었으면 먼저 `cd C:\ai-class\tumble-dashboard`를 칩니다.
- 올린 뒤에는 편집기 탭을 새로고침(F5)해야 새 함수가 함수 선택 목록에 보입니다. 함수 목록은 왼쪽에서 고른 파일 기준이라, 이번 회차 함수는 `Code.gs`를 누른 뒤 고릅니다.
- 이번 회차는 웹 앱의 응답을 바꾸지 않습니다. 그래서 **`gas:redeploy`는 하지 않습니다.** 편집기 실행과 트리거는 `gas:push`로 올린 코드로 바로 돌아갑니다.
- 화면은 10초마다 다시 조회합니다. 시트가 바뀐 뒤 10~15초 기다리면 화면에 반영됩니다. 화면 서버는 켜 둔 채로 진행합니다. 화면 파일은 이번 회차에 바뀌지 않습니다.
- 이 회차는 따라잡기와 발표 시간도 겸합니다. 프롬프트는 짧고, 대부분은 편집기와 시트에서 직접 확인합니다.
