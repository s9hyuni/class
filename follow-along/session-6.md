# 6회차: Discord 알림, 기록 처리, 트리거

- **시작 상태**: 5회차를 끝낸 `C:\ai-class\tumble-dashboard`에서 이어 합니다(완료 브랜치 `milestone-5`와 같은 출발점). 내 GAS 웹 앱이 배포돼 있고, 화면은 내 Google 시트 값으로 "조회 정상"이며 기록 보기도 됩니다.
- **끝나면 되는 것**
  - 내 Discord 시험 채널로 알림이 가고, 화면의 운영 상태 알림 카드에 "전송 성공"이 뜹니다.
  - GAS 편집기에서 함수를 실행하거나 시트를 직접 고쳐 기록을 더하고 처리하면 화면 수량이 바뀝니다.
  - 자동 실행(트리거) 두 개가 동작합니다. 하나는 시트를 고치면 바로 처리하고, 하나는 1분마다 늦은 기록을 알립니다. 실습이 끝나면 지웁니다.
- **준비물**: 5회차에 쓴 개인 Google 계정으로 로그인한 Chrome, Discord 계정(Chrome에서 https://discord.com 으로 써도 됩니다), 명령을 칠 PowerShell 창, 화면 서버를 켜 둘 PowerShell 창(이하 화면 창)

## 시작 전에 (프롬프트 없이 직접 합니다)

1. 화면 창에서 아래를 치고 Chrome에서 `http://127.0.0.1:4173`을 엽니다.

```powershell
cd C:\ai-class\tumble-dashboard
npm.cmd start
```

   서버를 켜 둔 창이 이미 있으면 이 명령을 치지 않고 주소만 엽니다.

2. AI 도구로 `C:\ai-class\tumble-dashboard` 폴더를 열고 새 대화를 시작합니다.
3. 아래 "수업 날 새 실습 시트 만들기"를 합니다.

### 수업 날 새 실습 시트 만들기

화면은 "오늘" 기록만 셉니다. 5회차에 만든 시트의 시드 기록은 그날 날짜라서 오늘 화면에는 기록이 없게 나옵니다. 오늘 날짜로 시드 기록이 든 새 시트를 만듭니다. 웹 앱은 다시 배포하지 않아도 새 시트를 읽습니다.

- 직접 하기: PowerShell 창에서 `cd C:\ai-class\tumble-dashboard`를 치고 `npm.cmd run gas:editor`로 편집기를 엽니다.
- 직접 하기: Chrome에 열린 편집기 오른쪽 위 계정이 5회차에 쓴 개인 Google 계정인지 봅니다. 왼쪽 파일 목록에서 `Setup.gs`를 누르고, 위쪽 함수 선택에서 `createTrainingSpreadsheet`를 골라 "실행"을 누릅니다.
- 확인: 실행 로그에 `새 실습 시트: https://docs.google.com/spreadsheets/…`가 나옵니다. 10~15초 안에 화면이 "생산 100개 · 목표 120개", "출고 75개 · 목표 100개"이고 "조회 정상"입니다.
- 이 시트는 이번 회차 내내 씁니다. 실행 로그의 주소를 Ctrl+클릭해 새 탭으로 열어 둡니다. 주소는 다른 곳에 옮기지 않습니다. 편집기 탭도 닫지 않고 둡니다.

## 진행 방법

- **꼭 지킬 것**: Discord 웹훅 주소를 아는 사람은 누구나 내 채널에 글을 보낼 수 있습니다. 주소는 GAS 스크립트 속성에만 넣고 채팅, AI 도구 대화창, 화면 공유, 캡처, 코드, 시트에 옮기지 않습니다. 오류를 AI 도구에 붙여 넣을 때도 `AKfyc`, `script.google.com`, `discord.com/api/webhooks`가 든 줄은 빼거나 강사에게 보여 줍니다.
- 프롬프트 상자 하나를 통째로 복사해 AI 도구 대화창에 붙여 넣습니다. 앞 번호가 끝난 뒤에 다음 번호를 보냅니다. 새 대화를 열 때마다 6-1의 프롬프트를 먼저 보낸 뒤 하던 번호부터 이어 갑니다.
- AI 도구가 바꾸려는 파일이나 실행할 명령을 물어보면 훑어보고 승인합니다. 도구마다 다를 수 있어서 묻지 않아도 문제가 아닙니다. 단 `icacls`, `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램을 바꾸는 명령은 승인하지 말고 강사에게 알립니다. 서버를 켜겠다고 하면 거절합니다. 6-1에서 수업 저장소를 받는 `git` 명령도 승인합니다. `npm.cmd run gas:`로 시작하는 명령은 그 번호의 프롬프트에 적힌 명령일 때만 승인합니다. `.clasp.json`, `.env`, `public\config.js`를 열겠다고 하면 승인하지 않습니다. `git commit`을 실행하겠다고 하면 승인하지 말고 "이건 제가 직접 합니다"라고 보냅니다.
- "직접 하기"는 AI 도구에 보내지 않고 내가 합니다. GAS 편집기에서 함수 실행, 스크립트 속성, 트리거 메뉴, 시트 고치기, Discord 설정은 내가 브라우저에서 합니다.
- AI 도구가 "이미 되어 있습니다"라고 답하면 그 번호의 "확인"만 해 보고 다음 번호로 넘어갑니다.
- 이번 회차 프롬프트는 Google 쪽 코드에 함수를 하나씩 더합니다. AI 도구는 내 컴퓨터의 파일만 고치고, Google에는 "올리고"가 붙은 번호(6-6, 6-11, 6-15)에서 올립니다. 올린 뒤에는 편집기 탭을 새로고침(F5)해야 새 함수가 함수 선택 목록에 보입니다. 함수 목록은 왼쪽에서 고른 파일 기준이라, 이번 회차 함수는 `Code.gs`를 누른 뒤 고릅니다.
- 이번 회차는 웹 앱의 응답을 바꾸지 않습니다. 그래서 **`gas:redeploy`는 하지 않습니다.** 편집기 실행과 트리거는 `gas:push`로 올린 코드로 바로 돌아갑니다.
- 화면은 10초마다 다시 조회합니다. 시트가 바뀐 뒤 10~15초 기다리면 화면에 반영됩니다. 화면 서버는 켜 둔 채로 진행합니다. 화면 파일은 이번 회차에 바뀌지 않습니다.
- 이 회차는 따라잡기와 발표 시간도 겸합니다. 프롬프트는 짧고, 대부분은 편집기와 시트에서 직접 확인합니다.

## 6-5. Discord 웹훅 만들어 스크립트 속성에 넣기 (직접 하기)

1. Discord에서 내가 만든 서버의 시험 채널을 고릅니다. 서버가 없으면 왼쪽 맨 아래 "+"(서버 추가하기), "직접 만들기"로 하나 만듭니다.
2. 채널 이름 옆 톱니바퀴(채널 편집), "연동", "웹후크", "새 웹후크"를 차례로 누릅니다. 새로 생긴 웹후크를 열고 "웹후크 URL 복사"를 누릅니다. 복사한 주소는 메모장이나 채팅에 붙여 넣지 않고 바로 다음 줄에서 씁니다.
3. GAS 편집기 왼쪽 톱니바퀴(프로젝트 설정)를 누르고 아래 "스크립트 속성"으로 내려갑니다.
4. "스크립트 속성 수정", "스크립트 속성 추가"를 누르고 속성에 `DISCORD_WEBHOOK_URL`, 값에 복사한 웹훅 주소를 붙여 넣은 뒤 "스크립트 속성 저장"을 누릅니다. 이미 있는 `SPREADSHEET_ID`, `TUMBLE_META`는 고치지 않습니다.

- 확인: 스크립트 속성 목록에 `DISCORD_WEBHOOK_URL`이 생겼습니다. 이 화면은 캡처하지 않습니다.

```text
접수 시각과 처리 시각을 채우는 끝부분은 다음 번호에서 만듭니다.
```

```text
설정 탭을 고쳤을 때는 설정 이력만 남깁니다. 자동 실행(트리거)을 만드는 일은 뒤 번호에서 합니다.
```

## 6-15. 올리고 트리거 설치

```text
[6-15] 자동 실행 함수를 편집기에서 설치할 수 있도록, npm 명령 gas:push를 한 번 실행하고 올린 파일 수만 알려 주세요.
```

- 직접 하기: AI 답에 올린 파일이 5개라고 나오면 편집기 탭을 새로고침합니다. `Code.gs`에서 `installTrainingTriggers`를 골라 실행합니다. 새 승인 창이 나오면 "모두 선택"으로 승인합니다. 그다음 편집기 왼쪽 트리거(시계 모양) 메뉴를 엽니다.

- 알아 두기: 새 시트를 만든 지 30분이 넘었으면 1~2분 안에 시험 채널에 "새 기록이 늦게 들어오고 있습니다." 알림이 올 수 있습니다. 정상입니다(6-17에서 봅니다).

## 6-16. 시트를 고치면 바로 처리되는지 확인 (직접 하기)

- 직접 하기: 생산 기록 탭 빈 줄의 A칸에 `P-hand-1`, B칸에 수량 `5`를 쓰고, 발생 시각은 바로 위 줄의 C칸(발생 시각)만 복사해 붙여 넣습니다. **A칸은 복사하지 않습니다.** A칸에는 원본 메모가 들어 있어 메모까지 옮겨집니다.
- 확인: 세 칸을 다 채우고 몇 초 안에 접수·처리 시각이 채워지고 처리 상태가 "완료"가 됩니다.
- 알아 두기: 칸을 하나씩 채우는 동안 처리 상태가 "입력 확인 필요"가 되고, 시험 채널에 "텀블공장: 수량은 1~10000의 정수입니다." 같은 입력 알림이 한 번 갈 수 있습니다. 세 칸을 다 채우면 "완료"로 바뀝니다.
- 직접 하기: `P-seed-0`의 수량을 25로 바꿉니다.
- 확인: 몇 초 안에 20으로 돌아옵니다. 접수한 기록은 시트에서 고쳐도 원본으로 돌아갑니다.
- 직접 하기: 설정 탭 `factory_target`을 `150`으로 바꿉니다.
- 확인: 10~15초 안에 화면이 "목표 150개"가 됩니다. 확인했으면 `120`으로 되돌립니다.
- 알아 두기: 설정 값에 범위를 벗어난 값(예: 목표에 글자)을 쓰면 화면이 바뀌지 않습니다. 편집기 왼쪽 실행 메뉴에서 `onEditInstalled`의 오류 문구(예: "목표는 양의 정수 또는 빈칸입니다.")를 보고 값을 고칩니다.

## 6-17. 늦은 기록 자동 알림 확인 (직접 하기)

- 직접 하기: 설정 탭 `delay_minutes`를 `1`로 바꾸고 1~2분 기다립니다.
- 확인: 화면 두 현장이 "새 기록이 늦게 들어오고 있습니다."가 되고, 시험 채널에 아래 두 알림이 옵니다. 알림 기록 탭에는 사건 ID `FACTORY-FEED`, `WAREHOUSE-FEED`로 남습니다.
  - "텀블공장: 새 기록이 늦게 들어오고 있습니다. 담당자: 기록 담당자 / 할 일: 시트의 기록과 처리 상태를 확인해 주세요."
  - "물류창고: 새 기록이 늦게 들어오고 있습니다. 담당자: 기록 담당자 / 할 일: 시트의 기록과 처리 상태를 확인해 주세요."
- 확인: 앞에 "텀블공장: 텀블공장: "이나 "텀블공장: 물류창고: "처럼 이름이 두 번 붙지 않습니다.
- 직접 하기: 두 알림을 캡처해 둡니다. 메일 주소가 보이지 않게 합니다. 편집기 왼쪽 실행 메뉴를 열어 `checkRecordDelays`가 1분 간격으로, `onEditInstalled`가 시트를 고칠 때마다 실행된 줄이 보이는지 봅니다.
- 직접 하기: `delay_minutes`를 `30`으로 되돌립니다.
- 알아 두기: 같은 알림은 10분(`cooldown_minutes`) 안에는 다시 오지 않습니다.

## 6-18. 발표 준비 (직접 하기)

완성한 화면에서 아래 세 가지를 보여 줍니다. 캡처와 화면 공유에 웹훅 주소, GAS 웹 앱 주소, 시트 주소, 메일 주소가 보이지 않게 합니다.

- 직접 하기: **내 시트 값으로 도는 화면**을 보여 줍니다. 오늘 운영 화면의 생산·출고 카드와 "조회 정상", 운영 상태 알림 카드의 "전송 성공"입니다.
- 직접 하기: **기록이 화면까지 오는 길**을 보여 줍니다. 편집기에서 `addDemoProductionRecord`를 실행하고 10~15초 뒤 생산 수량이 10 오르는 것입니다. 트리거를 지운 뒤에도 됩니다.
- 직접 하기: **자동 알림**을 보여 줍니다. 6-17에서 시험 채널에 온 두 알림(캡처)과 알림 기록 탭의 `FACTORY-FEED`, `WAREHOUSE-FEED` 줄입니다.
- 확인: 세 가지를 모두 화면에서 보여 줄 수 있습니다.
- 덧붙일 이야기: 붙여 넣은 프롬프트 가운데 결과가 기대와 달랐던 것 하나와, 그때 보낸 수정 요청.

## 6-19. 내 코드 남겨 두기 (직접 하기)

화면 창이 아닌 PowerShell 창에서 아래를 한 줄씩 칩니다. 둘째 줄은 내 웹 앱 주소가 든 `public\config.js`를 커밋에서 빼는 줄입니다.

```powershell
git add -A
git reset -q public/config.js
git commit -m "6회차 Discord 알림과 트리거"
```

- 확인: `git status`를 치면 바뀐 파일로 `public/config.js` 하나만 보입니다. 웹훅 주소는 스크립트 속성에만 있어 커밋에 들어가지 않습니다.

## 6-20. 실습이 끝나면 트리거 지우기 (직접 하기)

발표 준비를 마친 뒤 마지막에 합니다.

- 직접 하기: 편집기 왼쪽 트리거(시계 모양) 메뉴를 열고, 두 줄 각각 오른쪽 점 세 개, "트리거 삭제", "완전삭제"를 누릅니다.
- 확인: 트리거 목록이 비었습니다.
- 알아 두기: 지우지 않으면 수업 뒤에도 1분마다 실행되고, 현장이 확인 필요인 동안 10분마다 알림이 옵니다. 무료 Google 계정은 트리거 실행 시간에 하루 한도가 있습니다.
- 알아 두기: 나중에 다시 쓰려면 `installTrainingTriggers`를 실행합니다. 새 실습 시트를 만든 뒤에도 다시 실행해야 합니다(시트를 고칠 때 도는 트리거는 만든 때의 시트에 걸립니다).

## 6회차 끝 확인

- [ ] 시험 채널에 "텀블공장: 알림 연결 테스트입니다."가 왔고, 알림 기록 탭에 `sent`·`HTTP 200` 줄이 있습니다.
- [ ] 화면 알림 카드가 "전송 성공", "알림 전송이 완료됐습니다."입니다.
- [ ] 웹훅 주소는 스크립트 속성 `DISCORD_WEBHOOK_URL`에만 있고, Google 쪽 코드와 시트에는 없습니다.
- [ ] `addDemoProductionRecord`로 생산 수량이 10 오릅니다.
- [ ] 시트에 손으로 쓴 기록이 몇 초 안에 "완료"가 되고, 접수한 기록의 수량을 바꾸면 원래 값으로 돌아옵니다.
- [ ] `delay_minutes`가 1이면 두 현장의 늦은 기록 알림이 1~2분 안에 옵니다.
- [ ] 6-19에서 내 코드를 커밋했습니다.
- [ ] 실습 뒤 트리거 목록이 비어 있습니다.
- [ ] 이번 회차에 `gas:redeploy`를 하지 않았고, `public\config.js`의 주소는 6-1을 시작할 때 그대로입니다.
