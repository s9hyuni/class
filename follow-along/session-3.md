# 3회차: 강사 API 연결과 과거 조회

- **시작 상태**: 2회차를 끝낸 `C:\ai-class\tumble-dashboard`에서 이어 합니다. 화면의 숫자·그래프·기록 표가 예시 자료로 채워지고, 주소별 화면, 알림 목록, 도움말이 동작합니다. 2회차를 못 끝냈으면 아래 "시작 전에"의 안내대로 `milestone-2` 브랜치를 새 폴더에 받습니다.
- **끝나면 되는 것**
  - 화면이 강사 API의 실제 값으로 채워지고 10초마다 다시 조회합니다. 새로고침 버튼으로 바로 조회할 수도 있습니다.
  - 조회가 실패해도 이전 값이 남고, 왜 실패했는지 노란 안내로 알려 줍니다.
  - 헤더에서 과거 시각을 골라 그때의 자료를 보고, 조회 기록 화면에서 이 탭이 보낸 요청을 막대와 표로 봅니다.
  - 예시 자료 파일(`public\sample-data.js`)이 없어집니다.
- **준비물**: Chrome, 인터넷, 서버를 켜 둘 PowerShell 창(이하 "서버 창"), 명령을 칠 PowerShell 창 하나 더, 프로젝트 맨 위의 `API_CONTRACT.md`(강사가 준 API 안내 파일)

| 번호 | 하는 일 |
|---|---|
| 3-1 ~ 3-4 | 강사 API에서 자료 받기 |
| 3-5 ~ 3-8 | 응답 전 화면, 새로고침 버튼, 조회 상태 |

| 3-27 ~ 3-34 | 조회 기록 남기기와 조회 기록 화면 |
| 3-35 ~ 3-36 | 기록 화면을 기준 시각에 맞추기 |

## 시작 전에 (프롬프트 없이 직접 합니다)

### 이번 회차 문서 받기

**2회차를 끝냈으면: 문서만 받습니다.** PowerShell 창에서 첫 줄부터 칩니다.

```powershell
cd C:\ai-class\tumble-dashboard
git fetch origin
git checkout origin/milestone-2 -- AGENTS.md docs/guide
```

- 확인: 파일 탐색기나 AI 도구의 파일 목록에서 `docs\guide`의 가장 큰 번호가 `session-3.md`입니다.
- 내 코드는 바뀌지 않습니다. AI 도구에 파일 변경 표시가 생겨도 그대로 둡니다. 커밋하지 않습니다.
- 첫 줄이나 둘째 줄에서 빨간 오류가 나오면 다음으로 가지 말고 강사에게 알립니다.
- 받는 두 줄(`git fetch`, `git checkout`)은 늘 함께 칩니다. `git fetch`를 빼면 오류 없이 옛 문서를 받습니다.
- `docs\guide` 안의 파일을 고치면 받을 때 경고 없이 저장소 판으로 덮입니다. 내 메모는 이 폴더 밖에 둡니다.
- 줄 끝의 `-- AGENTS.md docs/guide`를 빠뜨려 화면에 `detached HEAD`가 보이면 `git switch -`를 치고 강사에게 알립니다. `error:`로 끝나고 멈췄다면 아무것도 바뀌지 않은 것이니 명령을 다시 복사해 칩니다.
- 회차를 진행하는 중에 강사가 문서를 고쳤다고 알리면 이 명령을 한 번 더 칩니다. 내 코드는 그대로입니다.

**2회차를 못 끝냈으면: 완료 브랜치를 새 폴더에 받습니다.** 이 브랜치에 문서도 함께 들어 있습니다.

1. 켜 둔 서버를 모두 그 창에서 Ctrl+C로 끄고, 그 창들과 AI 도구를 닫습니다. 폴더를 쓰는 프로그램이 있으면 이름이 바뀌지 않을 수 있습니다.
2. PowerShell 창을 새로 열고 칩니다.

```powershell
cd C:\ai-class
Rename-Item tumble-dashboard tumble-dashboard-before-session-3
git clone -b milestone-2 https://github.com/startup-life/aiops-dashboard-student.git tumble-dashboard
```

빨간 오류가 나오면 다음으로 가지 말고 강사에게 알립니다.

3. GitHub 로그인 창이 뜨면 초대받은 계정으로 로그인합니다.
4. AI 도구로 새 `tumble-dashboard` 폴더를 엽니다. 내가 만든 코드는 `tumble-dashboard-before-session-3`에 남습니다.

### 서버와 강사 API 확인

1. 서버 창에서 아래 명령으로 서버를 켜고 Chrome에서 `http://127.0.0.1:4173`을 엽니다. 2회차 끝 확인이 맞는 상태에서 시작합니다.

```powershell
cd C:\ai-class\tumble-dashboard
npm.cmd start
```

서버를 켜 둔 창이 이미 있으면 이 명령을 치지 않고 주소만 엽니다.

2. 명령을 칠 PowerShell 창에서 `notepad C:\ai-class\tumble-dashboard\API_CONTRACT.md`로 열어 1절의 강사 API 주소를 찾습니다. Chrome 새 탭 주소창에 그 주소 뒤로 `/api/v1/snapshot`을 붙여 엽니다. JSON 글자가 보이면 됩니다. 화면 위의 "보기 좋게 표시"를 켜면 읽기 쉽습니다.
3. 그 화면에서 `sites` 아래 `factory`의 `completed`와 `target` 값을 찾아 적어 둡니다. 3-3에서 화면 숫자와 대조합니다.

## 진행 방법

- 프롬프트를 번호 순서대로 하나씩 AI 도구에 붙여 넣습니다. 앞 번호가 끝나기 전에 다음 번호를 보내지 않습니다.
- AI 도구가 바꾸려는 파일이나 실행할 명령을 물어보면 훑어보고 승인합니다. 도구마다 달라서 묻지 않아도 문제가 아닙니다. 단 `icacls`, `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램을 바꾸는 명령은 승인하지 말고 강사에게 알립니다. `.clasp.json`, `.env`를 열겠다고 하거나 `npm.cmd run gas:`, `npm.cmd start`, `git`을 실행하겠다고 하면 승인하지 말고 "이건 제가 직접 합니다"라고 보냅니다.
- 이번 회차는 화면 파일만 고치므로 서버는 켜 둔 채로 두고, 단계가 끝날 때마다 브라우저만 새로고침(F5)합니다.
- 요청은 F12(개발자 도구)의 Network 탭에서 봅니다. 새로고침한 뒤 목록에 `snapshot`, `records` 같은 줄이 생기고, 줄을 누르면 요청 주소와 상태(200 등)가 보입니다.
- Network 탭 위쪽의 속도 메뉴("제한 없음")에서 "느린 4G"(영문 화면은 Slow 4G)나 "오프라인"을 고를 수 있습니다. 확인이 끝나면 늘 "제한 없음"으로 되돌립니다.
- 강사 API의 상황은 강사가 바꿉니다. 수강생은 읽기만 합니다.
- 화면의 색과 배치는 예시와 조금 달라도 됩니다. 따옴표로 적은 문구와 각 단계의 "확인"에 적힌 동작은 같아야 합니다.

### 실패 상황 만드는 법 (3-8 ~ 3-23, 3-31에서 씁니다)

3-2에서 만드는 `public\config.js`를 내가 직접 고치고 저장한 뒤 새로고침합니다. 명령을 칠 PowerShell 창에서 `cd C:\ai-class\tumble-dashboard`를 친 다음 `notepad public\config.js`로 엽니다. 바꾸기 전 값을 적어 두고, 확인한 뒤 꼭 되돌립니다.

| 만들 실패 | 방법 |
|---|---|
| 정상 화면을 본 뒤의 실패 | Network 탭 속도 메뉴에서 "오프라인"을 고르고 헤더의 새로고침 버튼을 누릅니다 |
| 연결 실패(처음부터) | `apiBaseUrl` 값을 `"http://127.0.0.1:3999"`로 바꾸고 새로고침 |
| HTTP 404 | `apiBaseUrl` 값의 강사 API 주소 끝에 `/abc`를 붙이고 새로고침 |
| 시간 초과 | `timeoutMs` 값을 `100`으로 바꾸고 새로고침 |

`config.js`는 페이지를 열 때 한 번 읽습니다. 그래서 `config.js`를 바꾼 시험은 늘 "처음부터 실패한 화면"이 됩니다.

## 3-1. API 응답 읽어 보기

```text
[3-1] 강사가 준 API 안내 파일을 읽고, 지금 화면의 칸마다 강사 API 응답의 어느 값을 쓰는지 표로 알려 주세요.
화면이 쓰지 않는 값과 예시 자료와 다른 점도 알려 주세요. 파일은 바꾸지 마세요.
```
- 확인: 화면 칸과 응답 값을 짝지은 표가 답으로 나옵니다. 파일은 바뀌지 않습니다.

## 3-2. 연결 설정 파일 만들고 불러오기

```text
[3-2] 보충 문서 '연결 설정과 요청'대로 연결 설정 파일을 만들고 화면이 열릴 때 읽게 해 주세요.
주소는 강사 API 주소이고 예시 자료는 아직 그대로 둡니다.
```
- 확인: `http://127.0.0.1:4173/config.js`를 열면 네 줄이 보이고, 두 값이 `API_CONTRACT.md` 9절 표의 1단계 값과 글자까지 같습니다. 뒤 회차에서는 이 파일의 두 값만 바꿉니다.
- 확인: 새로고침한 뒤 F12 콘솔(Console 탭)에 `DASHBOARD_CONFIG`를 치고 Enter를 누르면 `apiBaseUrl`과 `timeoutMs` 두 값이 나옵니다.

## 3-3. 강사 API로 화면 채우기

```text
[3-3] 페이지를 열 때 강사 API에서 오늘 운영 자료를 한 번 받아 예시 자료 대신 화면을 채워 주세요.
요청과 받는 방식은 보충 문서 '연결 설정과 요청'대로 하고, 기록 표는 아직 예시 자료를 씁니다.
```
- 확인: Network 탭을 연 채 새로고침하면 `snapshot` 줄이 생기고 상태가 200입니다. 화면의 생산 수량과 목표가 시작 전에 적어 둔 `completed`·`target`과 같습니다.
- 확인: PC 폭에서 두 카드가 화면 안에 두 열로 들어오고 페이지에 가로 스크롤이 없습니다. 막대가 많으면 그래프 칸만 옆으로 밀립니다.
- 그래프 막대 수가 실제 응답의 `history` 개수와 같아집니다. 기록 화면은 예시 기록의 날짜가 오늘과 달라 "선택한 시간대에 기록이 없습니다."가 보일 수 있습니다(3-11에서 바뀝니다).

## 3-4. 자료가 없거나 틀려도 그리기

```text
[3-4] 기록 화면 주소로 바로 열어 자료가 아직 없을 때도 오류 없이 그려지게 하고, 그때의 칸 값은 보충 문서 '기록 화면'대로 해 주세요.
받은 자료는 화면에 쓰기 전에 보충 문서 '자료 다듬기'대로 틀린 칸만 비웁니다.
```
- 확인: 주소창에 `http://127.0.0.1:4173/#/records/factory`를 치고 열면 F12 콘솔에 빨간 오류가 없고, 시작 칸이 오늘 00:00:00입니다. 오늘 운영 화면은 그대로입니다.
- (선택) AI 도구에 "공장 시간별 기록 한 점의 수량이 글자 "abc"인 자료를 넣으면 공장과 창고의 시간별 기록이 어떻게 되는지 알려 주세요. 파일은 바꾸지 마세요."라고 묻습니다. 공장만 빈 목록이 되면 맞습니다.

- 사진 자리는 3-10까지 "현장 사진 확인 중"으로 남고, 그 아래 사진 설명 글자는 보이지 않습니다.

## 3-6. 새로고침 버튼: 조회 겹치지 않게

```text
[3-6] 헤더의 새로고침 버튼을 누르면 다시 조회하게 해 주세요. 페이지를 열 때의 첫 조회도 같은 방식으로 합니다.
조회 중에 누르면 새 요청을 보내지 않고, 조회 중에도 키보드 초점은 버튼에 남게 합니다.
```
- 확인: 버튼을 누르면 아이콘이 잠깐 돕니다. 버튼을 빠르게 여러 번 눌러도 Network 탭의 `snapshot` 줄이 겹쳐 쌓이지 않습니다.

## 3-7. 조회 상태와 조회 정보 줄

```text
[3-7] 본문 맨 위에 조회 정보 줄과 숨긴 노란 안내 상자를 두고, 헤더의 조회 상태와 함께 보충 문서 '조회 상태 보이기'대로 보여 주세요.

```
- 확인: 실패 상황 표의 "연결 실패"로 바꾸고 새로고침하면 "조회 실패"와 노란 안내가 보입니다. 안내 뒤쪽은 영어(`Failed to fetch` 등)여도 됩니다(3-20에서 바꿉니다). 확인한 뒤 되돌립니다.

## 3-9. 10초 자동 조회와 남은 초

```text
[3-9] 조회가 끝나면(성공이든 실패든) 응답이 온 뒤 10초 뒤에 다시 조회하고, 새로고침 버튼은 바로 조회한 뒤 다시 10초를 세게 해 주세요.
헤더에 남은 초를 보충 문서 '조회 방식'대로 보이고, 다른 탭에서 돌아왔을 때 다음 조회 시각이 지났으면 바로 조회합니다.
```
- 확인: Network 탭에 `snapshot` 줄이 약 10초 간격으로 하나씩 생기고, 그때마다 "마지막 조회 성공" 시각이 바뀝니다.
- 확인: 헤더에 "다음 조회 10초", "9초" … "1초", "조회 중…"이 되풀이됩니다. 세는 중에 새로고침 버튼을 누르면 바로 조회하고 다시 10초부터 셉니다.
- 확인: 다른 탭으로 옮겨 1분쯤 있다가 돌아오면, 돌아오자마자 `snapshot` 줄이 하나 생기고 남은 초가 10초부터 다시 시작합니다.

```text
[3-10] 카드 사진을 받은 자료의 사진 주소로 보여 주세요. 10초 조회 때 깜박이지 않게 합니다.
사진 아래 글과 사진이 없거나 못 불러올 때의 글은 보충 문서 '현장 사진'대로 합니다.
```
- 확인: 사진 위에서 오른쪽 클릭, [이미지 주소 복사]를 눌러 붙여 보면 강사 API 주소 뒤에 `/api/v1/images/factory`가 붙은 주소입니다. 자동 조회가 몇 번 지나도 사진이 깜박이지 않습니다.
- 사진은 처음 받을 때 수십 초 걸려 위부터 조금씩 채워질 수 있습니다. 그동안 사진 칸 아래쪽이 회색으로 보여도 기다리면 됩니다.
- 실패 상황 표의 "연결 실패"로 바꾸고 새로고침해도 사진 칸에 "현장 사진 확인 중"이 그대로 남을 수 있습니다(3-18에서 "현장 사진 없음"으로 바뀝니다). 바꿔 보았으면 확인한 뒤 되돌립니다.

## 3-11. 기록 표를 API로 채우기

```text
[3-11] 기록 화면의 표를 예시 기록 대신 강사 API의 오늘 기록으로 보충 문서 '기록 화면'대로 채워 주세요.
기록 화면에 있으면 10초 조회가 성공할 때마다 기록도 새로 받고, 기록 화면으로 들어오면 바로 조회합니다.
```
- 확인: "생산 기록 보기"를 누르면 오늘 00:00부터 지금까지의 실제 생산 기록이 보이고, Network 탭에 `records?kind=production&at=…` 줄이 생깁니다.

## 3-12. 기록 화면 안내

```text
[3-12] 기록을 받기 전, 기록 요청이 실패했을 때, 오늘 운영 자료를 받지 못해 기록을 못 받았을 때의 안내를 보충 문서 '기록 화면'대로 보여 주세요.
```
- 확인: 기록 화면을 새로고침하면 표가 나오기 전에 "기록을 확인하고 있습니다."가 잠깐 보입니다(빨라서 안 보일 수 있습니다).
- 확인: 실패 상황 표의 "연결 실패"로 바꾸고 `#/records/factory`를 새로고침하면 표 자리에 노란 "현재 자료를 받지 못해 기록을 불러오지 못했습니다. 다시 조회하면 불러옵니다."가 보입니다. 되돌리고 새로고침하면 표가 나옵니다.

## 3-13. "시간대 조회"와 칸 값

```text
[3-13] "시간대 조회"를 누르면 그때 칸의 시각을 기억하고 바로 조회해, 그 뒤 조회마다 그 시간대의 기록을 받게 해 주세요.
보내는 값과 칸에 보일 값은 보충 문서 '기록 화면'대로 하고, 입력하는 중인 칸은 덮어쓰지 않습니다.
```
- 확인: 시작 시각을 늦추고 "시간대 조회"를 누르면 `records` 요청 주소에 `from=`이 붙고 표가 줄어듭니다.
- 확인: 출고 기록 화면을 F5로 새로고침한 뒤 시작 칸만 고치고 누르지 않은 채 10초를 기다리면, 다음 `records` 주소에 `from=`이 없고 고친 글자는 칸에 그대로 남습니다. 새로고침 없이 옮기면 앞에서 누른 시간대가 남습니다. 비우는 일은 3-14에서 만듭니다.
- 확인: 기록 화면에서 아무것도 고치지 않고 10초 기다리면 종료 칸의 시각이 조회 때마다 늘어납니다. 시작 칸을 눌러 입력하는 중에는 조회가 지나가도 입력하던 값이 바뀌지 않습니다.

## 3-14. 다른 화면으로 옮길 때 비우기

```text
[3-14] 다른 화면으로 옮길 때마다 기억한 시간대, 고친 칸 값, 받아 둔 기록과 기록 오류를 비워 주세요. 생산 기록에서 출고 기록으로 바로 옮길 때도 같습니다.
```
- 확인: 시작 칸을 고치고 "시간대 조회"를 누른 뒤 "← 오늘 운영"으로 갔다가 "출고 기록 보기"로 들어오면, 시작 칸이 오늘 00:00:00이고 새 `records` 주소에 `from=`이 없습니다.

## 3-15. 같은 기록이면 표를 그대로

```text
[3-15] 10초 조회로 받은 기록이 지난번과 같으면 표를 다시 만들지 마세요. 달라서 다시 그릴 때는 표의 가로 스크롤 위치와 초점을 지킵니다.
```
- 확인: F12 기기 툴바로 휴대폰 폭(375px)을 만들고, 표를 오른쪽으로 민 뒤 Tab으로 표에 초점을 둡니다(초록 테두리). 10초 조회가 두 번 지나도 기록이 늘지 않았다면 민 위치와 초점 테두리가 그대로입니다.

## 3-16. 예시 자료 지우기

```text
[3-16] 예시 자료 파일과 그것을 부르는 줄을 지우고, 화면 코드에 예시 자료를 쓰는 곳이 남지 않게 해 주세요.
검증표 파일은 지우지 말고 맨 위에 보충 문서 '회차 끝 정리'대로 한 줄을 더해 주세요.
```
- 확인: 파일 탐색기나 AI 도구의 파일 목록에 `public\sample-data.js`가 없고, 새로고침해도 오늘 운영 화면과 기록 화면이 그대로 동작합니다.

## 3-17. 실패해도 마지막 자료 지키기

```text
[3-17] 조회가 실패해도 마지막으로 받은 자료는 지우지 말고 화면에 그대로 두세요.
노란 안내 끝에는 한 칸 띄우고, 이전 자료가 있으면 "아래 내용은 이전 조회 자료입니다.", 없으면 "조회할 자료가 없습니다."를 붙입니다.
```
- 확인: 정상 화면에서 Network 탭을 "오프라인"으로 바꾸고 새로고침 버튼을 누르면 숫자는 그대로이고, "조회 실패"와 끝이 "아래 내용은 이전 조회 자료입니다."인 노란 안내가 보입니다. "제한 없음"으로 되돌리면 다음 조회에서 안내가 사라집니다.

## 3-18. 처음부터 실패한 화면

```text
[3-18] 첫 조회부터 실패해 받은 자료가 없으면 빈 자료로 화면을 그려 "조회 중"이 남지 않게 해 주세요.
카드와 운영 상태의 글자는 보충 문서 '처음부터 실패한 화면'대로 합니다.
```
- 확인: 실패 상황 표의 "연결 실패"로 바꾸고 새로고침하면 카드에 "조회 중"이 남지 않고 "확인 불가"와 "현장 사진 없음"이 보입니다.
- 확인: 그 상태에서 "대기"·"확인 불가" 배지가 보이고, 노란 안내 끝이 "조회할 자료가 없습니다."입니다. 확인한 뒤 되돌립니다.

## 3-19. 실패 이유: 시간 초과

```text
[3-19] 시간 초과로 멈춘 조회는 보충 문서 '실패 문장'대로 실패하게 해 주세요. 답을 읽는 도중에 시간이 넘어도 같습니다.
```
- 확인: 실패 상황 표의 "시간 초과"로 바꾸고 새로고침하면 "서버가 0.1초 안에 응답하지 않았습니다. 잠시 후 다시 조회하고, …"가 보입니다. 확인한 뒤 되돌립니다.

## 3-20. 실패 이유: 연결 실패와 JSON 아님

```text
[3-20] 서버에 연결하지 못했을 때와 응답을 JSON으로 읽지 못했을 때를 보충 문서 '실패 문장'대로 실패하게 해 주세요.
```
- 확인: 실패 상황 표의 "연결 실패"로 바꾸고 새로고침하면 "API 서버에 연결하지 못했습니다. …"가 보입니다. 확인한 뒤 되돌립니다.
- JSON이 아닌 응답은 강사 API로 만들 수 없습니다. 4회차에 시험용 파일로 확인합니다.

## 3-21. 실패 이유: HTTP 오류와 서버가 알린 이유

```text
[3-21] HTTP 오류와 서버가 응답에 담아 보낸 오류를 보충 문서 '실패 문장'대로 실패하게 해 주세요.
HTTP 오류는 응답 내용을 읽지 않고 상태 번호로 문장을 정하고, 기록 조회도 같은 문장을 씁니다.
```
- 확인: 실패 상황 표의 "HTTP 404"로 바꾸고 새로고침하면 "서버에 요청한 주소가 없습니다(HTTP 404). 연결 주소를 확인해 주세요."가 보입니다. 확인한 뒤 되돌립니다.
- 확인: 기록 화면에서 시작 시각을 종료 시각보다 늦게 넣고 "시간대 조회"를 누르면 표 자리에 "서버가 요청 조건을 받아들이지 않았습니다(HTTP 400)."가 보입니다. 3-36을 마치면 이 요청은 보내기 전에 막히므로 지금 확인해 둡니다.
- 서버가 알린 이유는 4회차에 시험용 파일로 확인합니다.

## 3-22. 받은 자료 검사

```text
[3-22] 받은 오늘 운영 자료와 기록 자료를 보충 문서 '자료 검사'대로 검사해, 처음 틀린 칸 하나를 안내 문장으로 알리고 실패로 처리해 주세요.
틀리면 마지막 성공 자료를 덮어쓰지 않고, 기록은 표 대신 노란 안내로 보입니다.
```
- 확인: AI 도구에 "오늘 운영 자료 검사에 판 번호가 0인 자료, 첫 알림 항목의 등급이 "info"인 자료를 넣으면 무엇을 돌려주는지 보여 주세요. 파일은 바꾸지 마세요."라고 묻습니다. "… 틀린 항목: revision (기대: 1 이상의 정수)", "서비스 상태의 형식을 확인해 주세요. 틀린 항목: incidents[0].level (기대: "warning" 또는 "error")"이면 맞습니다.
- 확인: 기록 화면의 표가 그대로 보입니다.

## 3-23. 조회 실패 알림

```text
[3-23] 조회가 실패한 동안 헤더 알림 건수, 알림 목록, 먼저 확인할 일의 맨 앞에 조회 실패 항목 하나를 더해 주세요.
글자와 자료가 없을 때의 알림 버튼은 보충 문서 '조회 실패 알림'대로 하고, 알림이 있어도 생산·출고 수량은 바꾸지 않습니다.
```
- 확인: Network 탭을 "오프라인"으로 바꾸고 새로고침 버튼을 누르면 헤더가 붉은 "알림 N건"이 되고, 알림 목록 맨 위가 "최신 자료를 가져오지 못했습니다."입니다. "제한 없음"으로 되돌리면 다음 조회에서 사라집니다.
- 확인: "오프라인"으로 바꾸고 새로고침 버튼을 누르면 먼저 확인할 일에 "최신 자료를 가져오지 못했습니다.", "담당자: 서비스 운영 담당자", "확인할 일: 새로고침 후에도 실패하면 담당자에게 문의하세요. 조회 연결과 서버 상태를 확인해 주세요."가 보입니다. 확인한 뒤 "제한 없음"으로 되돌립니다.
- 확인: 실패 상황 표의 "연결 실패"로 바꾸고 새로고침하면 헤더가 붉은 "알림 1건"입니다. 확인한 뒤 되돌립니다.

## 3-24. 기준 시각 목록

```text
[3-24] 헤더의 기준 시각 목록을 보충 문서 '기준 시각 목록'대로 채워 주세요.
미래 시각은 넣지 않고, 목록을 열어 고르는 중에는 10초 조회가 와도 다시 만들지 않습니다.
```
- 확인: 기준 시각 상자를 열면 "현재", "00:00", "01:00" … 지금까지의 정시가 보이고, 맨 끝에 "(최근 조회)"가 붙은 시각이 보입니다.
- 확인: 기준 시각 상자를 눌러 목록을 연 채로 10초 조회가 지나가게 둡니다. 목록이 닫히거나 고르던 위치가 바뀌지 않습니다.

## 3-25. 과거 시각으로 조회하기

```text
[3-25] 과거 시각을 고르면 그 시각의 자료를 받고 자동 조회와 남은 초 글자를 멈추고, "현재"로 돌아오면 다시 시작해 주세요.
그 밖의 동작은 보충 문서 '과거 시각 조회'대로 합니다.
```
- 확인: "10:00"처럼 이른 정시를 고르면 화면이 잠깐 "조회 중"이 되었다가 고른 시각의 값으로 바뀝니다. 남은 초 글자가 사라지고, 그래프 막대가 줄고 수량이 작아집니다.
- 확인: 1분 넘게 기다려도 새 `snapshot` 줄이 생기지 않고, 새로고침 버튼을 누르면 `snapshot?at=…` 줄이 하나 생깁니다. 노란 안내는 뜨지 않습니다(강사 API는 고른 시각 그대로 답합니다).

## 3-26. 과거 자료 안내와 "현재로 돌아가기"

```text
[3-26] 조회 정보 줄 뒤 칸의 안내와 과거 시각일 때의 "현재로 돌아가기" 버튼을 보충 문서 '과거 시각 조회'대로 보여 주세요.
버튼을 누르면 "현재"로 돌아가 자동 조회를 다시 시작하고, 열린 알림 목록은 닫히지 않습니다.
```
- 확인: 과거 시각에서 본문 위에 "… 10:00:00 기준 · 과거 자료"와 밑줄 친 "현재로 돌아가기"가 보입니다. 누르면 "다음 조회 10초"가 다시 보입니다.
- 확인: 과거 시각에서 헤더의 알림 버튼으로 목록을 연 채 "현재로 돌아가기"를 누르면 목록이 열린 채로 남습니다. 빈 곳을 누르면 닫힙니다.

## 3-27. 조회 기록 남기고 저장하기

```text
[3-27] 조회를 한 번 할 때마다 보충 문서 '조회 기록'대로 한 건을 남기고, 이 탭에 최근 200건만 저장해 페이지를 열 때 다시 읽어 와 주세요.
기준 시각이나 화면 주소가 바뀌어 버린 응답도 한 건으로 남깁니다.
```
- 확인: F12 Application 탭, 왼쪽 Session storage에서 `http://127.0.0.1:4173`을 누르면 `tumble-query-log` 줄이 있고 10초마다 값이 길어집니다.

## 3-28. 떠나는 중에 끊긴 요청은 빼기

```text
[3-28] 페이지를 떠나거나 새로고침하는 중에 끊긴 요청은 실패로 보지 말고 조회 기록에도 남기지 마세요. 떠날 때 확인 창은 띄우지 않습니다.
```
- 확인: 새로고침할 때 "사이트를 새로고침하시겠습니까?" 같은 확인 창이 뜨지 않습니다. 실패가 남지 않는지는 3-34 뒤에 확인합니다.

## 3-29. 데이터 조회 기록 카드

```text
[3-29] 오늘 운영의 "공장 조회"·"창고 조회" 카드에 마지막 조회와 응답시간을 보충 문서 '조회 기록 카드'대로 보여 주세요.
```
- 확인: 오늘 운영 아래쪽 "공장 조회", "창고 조회" 카드에 10초마다 새 시각과 새 응답시간이 보입니다.
- 확인: 새 탭에서 같은 주소를 열면 그 탭은 "조회 기록 없음"에서 시작합니다(탭마다 따로 남습니다).

## 3-30. 조회 기록 화면: 맨 위 카드

```text
[3-30] 조회 기록 화면 맨 위 카드에 제목과 마지막 조회 결과를 보충 문서 '조회 기록 화면'대로 보여 주세요. 조회 기록이 없을 때의 글도 같습니다.
```
- 확인: 오늘 운영의 "공장 조회" 카드에서 "전체보기"를 누르면 "생산 데이터 조회"와 "자료 제공"이 보입니다.
- 확인: 새 탭에서 `http://127.0.0.1:4173/#/queries/factory`를 열면 첫 응답 전 아주 잠깐 "조회 기록 없음"이 보일 수 있습니다(빨라서 안 보여도 됩니다).

## 3-31. 조회 기록 화면: 막대 줄

```text
[3-31] 조회 기록 화면 맨 위 카드 안에 조회 한 번마다 막대 하나를 오래된 것부터 한 줄로 놓아 주세요. 막대 색은 결과 색과 같습니다.
막대 글과 모양은 보충 문서 '조회 기록 화면'대로 합니다.
```
- 확인: 초록 막대가 높이 64px 정도로 나란히 보이고 10초마다 하나씩 늘어납니다. 빨간 막대를 보려면 실패 상황 표의 "연결 실패"로 바꿔 새로고침한 뒤 되돌립니다. 그때의 막대가 빨강입니다.
- 확인: 막대에 마우스를 올리면 시각·결과·응답시간이 뜹니다.

## 3-32. 조회 기록 화면: 막대 아래 글

```text
[3-32] 막대 줄 아래에 성공률 줄, 색 설명, 고른 막대 안내 글을 보충 문서 '조회 기록 화면'대로 두어 주세요.
막대를 누르거나 막대에 초점이 가면 안내 글을 그 막대의 글로 바꿉니다.
```
- 확인: 막대 아래에 "조회 성공률 …% · …건"과 색 설명 글이 보입니다.
- 확인: 막대를 누르면 아래 글이 그 조회의 시각·결과·응답시간으로 바뀝니다. Tab으로 막대를 옮겨 다닐 때도 바뀝니다.

## 3-33. 조회 기록 화면: 기록 표

```text
[3-33] 카드 아래에 최신 조회부터 표를 그려 주세요. 열과 칸 글은 보충 문서 '조회 기록 화면'대로 하고 기록 화면 표처럼 옆으로 밀립니다.
```
- 확인: 막대 아래에 표가 보이고 맨 윗줄이 가장 최근 조회입니다. 생산 화면과 출고 화면의 요청 시각이 같습니다(공장·창고를 한 요청으로 조회하기 때문입니다).

## 3-34. 다시 그려도 위치와 고른 막대 지키기

```text
[3-34] 조회 기록 화면을 10초마다 다시 그려도 막대 줄과 표의 가로 스크롤 위치, 초점, 고른 막대의 글을 지켜 주세요.
화면 주소가 바뀐 뒤 처음 그릴 때는 지키지 않고 고른 막대도 잊습니다.
```
- 확인: 휴대폰 폭(375px)에서 막대 줄을 옆으로 밀어 두고 10초 조회가 지나가게 둡니다. 막대가 하나 늘어도 민 위치가 그대로입니다.
- 확인: 막대 하나를 누르고 10초 조회가 지나가도 아래 글은 고른 막대의 글 그대로입니다. Tab으로 막대에 초점을 둔 채 조회가 지나가도 초점 테두리가 같은 막대에 남고, Enter를 누르면 그 막대의 글이 나옵니다.
- 확인: "← 오늘 운영"으로 갔다가 "전체보기"로 다시 들어오면 아래 글이 처음 안내로 돌아갑니다.
- 확인(3-28): Network 탭 속도를 "느린 4G"로 두고 헤더가 "조회 중…"일 때 F5로 새로고침하기를 세 번 합니다. "제한 없음"으로 되돌린 뒤 이 화면 표에 "실패" 줄이 새로 생기지 않았습니다.

## 3-35. 기록 화면을 기준 시각에 맞추기

```text
[3-35] 기록 화면의 시작·종료 칸을 기준 시각에 맞춰, 고를 수 있는 범위와 기본값을 기준 시각 날짜의 00:00:00부터 기준 시각(초까지)으로 해 주세요.
기준 시각은 보충 문서 '기록 화면'대로 정하고, 기록이 없을 때 가짜 기록을 만들지 않습니다.
```
- 확인: 기준 시각을 "10:00"으로 고르고 생산 기록 화면을 열면 종료 칸이 10:00:00이고, 표에는 그때까지의 기록만 보입니다. 종료 칸을 기준 시각보다 늦게 고르려 하면 입력 칸이 막거나 "시간대 조회" 때 브라우저 안내가 뜹니다.

## 3-36. 끝 시각이 시작보다 이르면 막기

```text
[3-36] 시작·종료 칸 값이 바뀔 때마다 종료가 시작보다 이르면 종료 칸에 "끝 시각은 시작 시각과 같거나 늦어야 합니다." 안내를 걸어 두고, 같거나 늦으면 바로 풀어 주세요.
안내가 걸린 채 "시간대 조회"를 누르면 요청하지 않고 그 안내를 띄웁니다.
```
- 확인: 시작 시각을 종료 시각보다 늦게 넣고 "시간대 조회"를 누르면 Network 탭에 새 `records` 줄이 생기지 않고 종료 칸에 "끝 시각은 시작 시각과 같거나 늦어야 합니다."가 뜹니다. 종료를 시작보다 늦게 고치면 바로 다시 누를 수 있고, 시작과 종료를 같게 두면 조회됩니다.
- 확인: 강사가 공장 지연 상황(`factory-delay`)으로 바꾼 뒤 현재 생산 기록 화면을 보면 마지막 줄이 "10개", 서버 접수 "접수 대기", 서버 처리 "처리 대기", 상태 "접수 대기"입니다. 강사 안내에 맞춰 확인합니다.

## 3회차 끝 확인

- [ ] 생산·출고 수량, 그래프, 상태가 강사 API 값과 같고, 사진 주소가 강사 API 주소입니다.
- [ ] Network 탭 "느린 4G"로 새로고침하면 화면 틀과 "조회 중"이 먼저 보이고, "0개"로 보이지 않습니다.
- [ ] "다음 조회 10초"부터 세고 조회하며, "마지막 조회 성공" 시각이 바뀝니다. 사진이 깜박이지 않습니다.
- [ ] 새로고침 버튼을 연달아 눌러도 `snapshot` 요청이 겹치지 않습니다.
- [ ] 다른 탭에 오래 있다가 돌아오면 바로 한 번 조회합니다.
- [ ] 정상 화면 뒤 "오프라인"이면 이전 숫자가 남고 "조회 실패", 안내 끝이 "아래 내용은 이전 조회 자료입니다."입니다.
- [ ] 처음부터 실패하면 "조회 중" 없이 "확인 불가"·"대기"가 보이고, 안내 끝이 "조회할 자료가 없습니다."입니다.
- [ ] 연결 실패, HTTP 404, 시간 초과(0.1초)의 실패 문장이 각각 다릅니다. 기록 HTTP 400 문장은 3-21에서 본 것으로 합니다.
- [ ] 실패 중이면 "최신 자료를 가져오지 못했습니다."가 알림 맨 앞에 오고 알림 버튼이 붉습니다.
- [ ] 과거 시각에서는 남은 초와 자동 조회가 멈추고, "현재로 돌아가기"로 돌아옵니다.
- [ ] 기준 시각 목록을 연 채로 10초 조회가 지나도 목록이 닫히거나 위치가 바뀌지 않습니다.
- [ ] 기록 화면에 실제 기록이 보이고 "시간대 조회"가 동작합니다. 다른 화면에 갔다 오면 칸이 기본값이고, 같은 기록이면 10초 조회 뒤에도 표의 위치와 초점이 남고, 기준 시각까지의 기록만 보입니다.
- [ ] 시작이 종료보다 늦으면 요청 없이 종료 칸에 "끝 시각은 시작 시각과 같거나 늦어야 합니다."가 뜹니다.
- [ ] 조회 기록이 요청 한 번에 한 건 남고, 새로고침 뒤에도 남으며, 새 탭은 따로 시작합니다. 조회 중 새로고침은 실패로 남지 않습니다.
- [ ] 조회 기록 화면에 색 막대, 성공률, 최신순 표가 보이고, 10초 조회 뒤에도 고른 막대의 글·초점·막대 줄 위치가 남습니다.
- [ ] 파일 탐색기나 AI 도구의 파일 목록에 `public\sample-data.js`가 없습니다.

이 회차의 자세한 내용은 [보충 문서](../docs/guide/session-3.md)에 있습니다.
