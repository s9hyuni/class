# 3회차: 강사 API 연결과 과거 조회

- **시작 상태**: 2회차를 끝낸 `C:\ai-class\tumble-dashboard`에서 이어 합니다. 화면의 숫자·그래프·기록 표가 예시 자료로 채워지고, 주소별 화면, 알림 목록, 도움말이 동작합니다.
- **끝나면 되는 것**
  - 화면이 강사 API의 실제 값으로 채워지고 10초마다 다시 조회합니다. 새로고침 버튼으로 바로 조회할 수도 있습니다.
  - 조회가 실패해도 이전 값이 남고, 왜 실패했는지 노란 안내로 알려 줍니다.
  - 머리 부분에서 과거 시각을 골라 그때의 자료를 보고, 조회 기록 화면에서 이 탭이 보낸 요청을 막대와 표로 봅니다.
  - 예시 자료 파일(`public\sample-data.js`)이 없어집니다.
- **준비물**: Chrome, 인터넷, 서버를 켜 둘 PowerShell 창(이하 "서버 창"), 명령을 칠 PowerShell 창 하나 더(이하 "명령 창"), 프로젝트 맨 위의 `API_CONTRACT.md`(강사가 준 API 안내 파일)

## 시작 전에 (프롬프트 없이 직접 합니다)

1. 서버 창에서 아래 명령으로 화면 서버를 켜고 Chrome에서 `http://127.0.0.1:4173`을 엽니다. 2회차 끝 확인이 맞는 상태에서 시작합니다.

```powershell
cd C:\ai-class\tumble-dashboard
npm.cmd start
```

서버를 켜 둔 창이 이미 있으면 이 명령을 치지 않고 주소만 엽니다.

2. AI 도구로 `C:\ai-class\tumble-dashboard` 폴더를 열고 새 대화를 시작합니다.

## 진행 방법

- 프롬프트 상자 하나를 통째로 복사해 AI 도구에 붙여 넣습니다. 앞 번호가 끝난 뒤에 다음 번호를 보냅니다.
- 제목에 "(직접 하기)"가 붙은 번호와 "직접 하기" 줄은 AI 도구에 보내지 않고 내가 직접 합니다.
- AI 도구가 바꾸려는 파일이나 실행할 명령을 물어보면 훑어보고 승인합니다. 도구마다 달라서 묻지 않아도 문제가 아닙니다. 3-1에서 수업 저장소를 받는 `git` 명령도 승인합니다. 단 `icacls`, `Set-ExecutionPolicy`, `npm audit fix`처럼 컴퓨터 설정이나 프로그램을 바꾸는 명령은 승인하지 말고 강사에게 알립니다. `.clasp.json`, `.env`를 열겠다고 하거나 `npm.cmd start`, `git commit`을 실행하겠다고 하면 승인하지 말고 "이건 제가 직접 합니다"라고 보냅니다.
- 이번 회차는 화면 파일만 고치므로 서버는 켜 둔 채로 두고, 번호가 끝날 때마다 브라우저만 새로고침(F5)하고 "확인"을 봅니다.
- "확인"과 다르게 나오면 화면의 글이나 F12 콘솔(Console 탭)의 빨간 줄을 그대로 복사해 "이렇게 나와요. 고쳐 주세요."와 함께 AI 도구에 붙여 넣습니다.
- AI 도구가 "이미 되어 있습니다"라고 답하면 그 번호의 "확인"만 해 보고 다음 번호로 넘어갑니다. 앞 번호에서 먼저 만들어졌을 수 있습니다.
- 답이 이상해지면 새 대화를 열고 3-1의 프롬프트를 다시 보낸 뒤, 하던 번호부터 이어 갑니다.
- 요청은 F12(개발자 도구)의 Network 탭에서 봅니다. 새로고침한 뒤 목록에 `snapshot`, `records` 같은 줄이 생기고, 줄을 누르면 요청 주소와 상태(200 등)가 보입니다.
- Network 탭 위쪽의 속도 메뉴("제한 없음")에서 "느린 4G"(영문 화면은 Slow 4G)나 "오프라인"을 고를 수 있습니다. 확인이 끝나면 늘 "제한 없음"으로 되돌립니다.
- 강사 API의 상황은 강사가 바꿉니다. 수강생은 읽기만 합니다.
- 화면의 색과 배치는 예시와 조금 달라도 됩니다. 따옴표로 적은 문구와 각 번호의 "확인"에 적힌 동작은 같아야 합니다.

## 3-3. 강사 API로 화면 채우기

```text
[3-3] 화면에 실제 운영 값을 보이기 위해, 페이지를 열 때 강사 API에서 오늘 운영 자료를 한 번 받아 예시 자료 대신 화면을 채우는 기능을 추가해 주세요.
받은 자료는 틀린 칸만 비우고 쓰며, 기록 화면 주소로 바로 열어 자료가 아직 없어도 오류 없이 그립니다.
기록 표는 아직 예시 자료를 쓰고, 10초 조회와 새로고침 버튼은 뒤 번호에서 만듭니다.
자세한 내용은 docs/guide/session-3.md의 "연결 설정과 요청", "자료 다듬기"와 "기록 화면"을 참고해 주세요.
```
- 확인: Network 탭을 연 채 새로고침하면 `snapshot` 줄이 생기고 상태가 200입니다. 명령 창에서 `notepad C:\ai-class\tumble-dashboard\API_CONTRACT.md`로 1절의 강사 API 주소를 찾아, Chrome 새 탭에서 그 주소 뒤에 `/api/v1/snapshot`을 붙여 열면 `sites` 아래 `factory`의 `completed`·`target`이 화면의 생산 수량·목표와 같습니다.
- 확인: 주소창에 `http://127.0.0.1:4173/#/records/factory`를 치고 열면 F12 콘솔에 빨간 오류가 없고, 시작 칸이 오늘 00:00:00입니다. 표는 예시 기록의 날짜가 오늘과 달라 "선택한 시간대에 기록이 없습니다."가 보일 수 있습니다(3-9에서 바뀝니다).

```text

숫자 0은 보이지 않게 하고, 페이지를 막 열었을 때와 자료가 없어 다시 그릴 때도 같은 글자를 씁니다.
```

- 확인: Network 탭 속도를 "느린 4G"로 두고 새로고침하면 머리 부분과 카드 틀, "자료 확인 중", "조회 중", "시간별 기록 조회 중"이 먼저 보이고 값이 나중에 채워집니다. "0개"는 보이지 않습니다. 확인한 뒤 "제한 없음"으로 되돌립니다.
- 사진 자리는 3-8까지 "현장 사진 확인 중"으로 남고, 그 아래 사진 설명 글자는 보이지 않습니다.

## 3-5. 10초 자동 조회와 새로고침 버튼

```text
[3-5] 화면이 늘 최신 값을 보이도록, 응답이 온 뒤 10초마다 다시 조회하는 자동 조회와 머리 부분의 새로고침 버튼 조회를 추가해 주세요.
첫 조회도 같은 방식으로 하고, 조회 중에는 새로 보내지 않으며 버튼의 키보드 초점을 지킵니다. 머리 부분에 다음 조회까지 남은 초를 보입니다.
조회 상태와 조회 정보 줄은 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-3.md의 "조회 방식"을 참고해 주세요.
```
- 확인: 머리 부분에 "다음 조회 10초", "9초" … "1초", "조회 중…"이 되풀이되고, Network 탭에 `snapshot` 줄이 약 10초마다 하나씩 생깁니다. 세는 중에 새로고침 버튼을 누르면 바로 조회하고 다시 10초부터 셉니다.
- 확인: 새로고침 버튼을 빠르게 여러 번 눌러도 `snapshot` 줄이 겹쳐 쌓이지 않고, 누르는 동안 아이콘이 잠깐 돕니다.

```text
본문 맨 위에는 노란 실패 안내 자리도 숨겨 두고, 실패 안내는 다음 번호에서 씁니다.
자세한 내용은 docs/guide/session-3.md의 "조회 상태 보이기"를 참고해 주세요.
```

## 3-7. 실패 안내와 마지막 자료 지키기

```text
[3-7] 강사 API에서 자료를 받지 못해도 화면을 계속 볼 수 있도록, 조회가 실패하면 본문 위에 노란 실패 안내를 추가해 주세요.
성공하면 안내를 숨기고, 실패해도 마지막으로 받은 자료는 그대로 두며, 처음부터 실패하면 빈 자료로 그립니다.
실패 이유별 문장은 뒤 번호에서 만듭니다.
자세한 내용은 docs/guide/session-3.md의 "조회 상태 보이기"와 "처음부터 실패한 화면"을 참고해 주세요.
```
- 확인: 평소 화면에는 노란 안내가 없고, AI 도구의 답에 실패 안내를 넣었다는 말이 있습니다. 실제 실패 화면은 3-17에서 한 번에 봅니다.

## 3-8. 현장 사진

```text
[3-8] 현장 모습을 실제 자료로 보이기 위해, 생산·출고 카드의 사진 칸에 받은 자료의 사진 주소로 그리는 현장 사진과 사진 아래 설명 글을 추가해 주세요.
10초 조회 때 깜박이지 않게 하고, 사진이 없거나 불러오지 못할 때 사진 자리에 보일 글도 넣습니다.
자세한 내용은 docs/guide/session-3.md의 "현장 사진"을 참고해 주세요.
```
- 확인: 사진 위에서 오른쪽 클릭, [이미지 주소 복사]를 눌러 붙여 보면 강사 API 주소 뒤에 `/api/v1/images/factory`가 붙은 주소입니다. 자동 조회가 몇 번 지나도 사진이 깜박이지 않습니다.
- 사진은 처음 받을 때 수십 초 걸려 위부터 조금씩 채워질 수 있습니다. 그동안 사진 칸 아래쪽이 회색으로 보여도 기다리면 됩니다.

## 3-9. 기록 표를 강사 API로

```text
[3-9] 기록 화면에서 실제 기록을 보도록, 기록 화면의 표를 예시 기록 대신 강사 API의 오늘 기록으로 채우는 기능을 추가해 주세요.
기록 화면에 있으면 조회가 성공할 때마다 기록도 새로 받고 들어오면 바로 조회하며, 표 자리에는 받기 전과 실패했을 때의 안내를 둡니다.
"시간대 조회"를 누른 시간대로 받는 일은 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-3.md의 "기록 화면"을 참고해 주세요.
```
- 확인: "생산 기록 보기"를 누르면 오늘 00:00부터 지금까지의 실제 생산 기록이 보이고, Network 탭에 `records?kind=production&at=…` 줄이 생깁니다.
- 확인: 기록 화면을 새로고침하면 표가 나오기 전에 "기록을 확인하고 있습니다."가 잠깐 보입니다(빨라서 안 보일 수 있습니다).

## 3-10. 시간대 조회와 화면 옮길 때 비우기

```text
[3-10] 원하는 시간대의 기록만 보도록, 기록 화면의 "시간대 조회"에 누른 순간의 칸 시각을 기억해 그 뒤 조회마다 그 시간대로 받는 기능을 추가해 주세요.
누르지 않은 칸 값은 요청에 쓰지 않고, 입력 중인 칸은 덮어쓰지 않으며, 고치지 않은 칸은 조회마다 기본값을 따라갑니다.
다른 화면으로 옮길 때마다(생산과 출고 사이도) 기억한 시간대, 고친 칸 값, 받아 둔 기록과 기록 오류를 비웁니다.
자세한 내용은 docs/guide/session-3.md의 "기록 화면"을 참고해 주세요.
```
- 확인: 출고 기록 화면을 F5로 새로고침한 뒤 시작 칸만 고치고 누르지 않은 채 10초를 기다리면, 다음 `records` 주소에 `from=`이 없고 고친 글자는 칸에 그대로 남습니다. 이어서 "시간대 조회"를 누르면 `records` 요청 주소에 `from=`이 붙고 표가 줄어듭니다.
- 확인: 시간대를 조회한 뒤 "← 오늘 운영"으로 갔다가 "출고 기록 보기"로 들어오면, 시작 칸이 오늘 00:00:00이고 새 `records` 주소에 `from=`이 없습니다.

## 3-11. 같은 기록이면 표 그대로

```text
자세한 내용은 docs/guide/session-3.md의 "기록 화면"을 참고해 주세요.
```
- 확인: F12 기기 툴바로 휴대폰 폭(375px)을 만들고, 표를 오른쪽으로 민 뒤 Tab으로 표에 초점을 둡니다(초록 테두리). 10초 조회가 두 번 지나도 기록이 늘지 않았다면 민 위치와 초점 테두리가 그대로입니다.

## 3-14. 실패 이유: HTTP 오류와 서버가 알린 이유

```text
[3-14] 서버 쪽 문제도 구별하도록, 노란 실패 안내에 HTTP 오류와 서버가 응답에 담아 보낸 오류의 안내 문장을 추가해 주세요.
HTTP 오류는 응답 내용을 읽지 않고 상태 번호로 문장을 정하며, 기록 조회도 같은 문장을 씁니다.
서버가 응답에 오류를 담아 보냈으면 정상 응답이어도 실패로 봅니다.
자세한 내용은 docs/guide/session-3.md의 "실패 문장"을 참고해 주세요.
```
- 확인: 기록 화면에서 시작 시각을 종료 시각보다 늦게 넣고 "시간대 조회"를 누르면 표 자리에 "서버가 요청 조건을 받아들이지 않았습니다(HTTP 400)."가 보입니다. 3-25를 마치면 이 요청은 보내기 전에 막히므로 지금 확인해 둡니다.

```text
자료가 없을 때의 알림 버튼 글자와 색도 함께 맞추고, 알림이 있어도 생산·출고 수량은 바꾸지 않습니다.
```

## 3-17. 실패 화면 확인 (직접 하기)

프롬프트는 없습니다. 3-7부터 만든 실패 안내를 두 가지 실패로 한 번에 봅니다.

1. **정상 화면을 본 뒤의 실패**: 오늘 운영 화면에서 Network 탭 속도 메뉴의 "오프라인"을 고르고 머리 부분의 새로고침 버튼을 누릅니다.
   - 확인: 숫자는 그대로이고 머리 부분이 "조회 실패", 노란 안내 끝이 "아래 내용은 이전 조회 자료입니다."입니다. 알림 버튼은 붉은 "알림 N건"이고, 알림 목록과 먼저 확인할 일의 맨 앞이 "최신 자료를 가져오지 못했습니다."입니다.
   - "제한 없음"으로 되돌리면 다음 조회에서 안내와 그 알림이 사라집니다.
2. **처음부터 실패**: 명령 창에서 `notepad C:\ai-class\tumble-dashboard\public\config.js`로 열어 `apiBaseUrl` 값을 `"http://127.0.0.1:3999"`로 바꿔 저장하고 새로고침합니다. `config.js`는 페이지를 열 때 한 번 읽으므로 늘 새로고침한 뒤에 봅니다.
   - 확인: 카드에 "조회 중"이 남지 않고 "확인 불가", "대기", "현장 사진 없음"이 보입니다. 노란 안내가 "현재 자료를 가져오지 못했습니다. API 서버에 연결하지 못했습니다. …"로 시작해 "조회할 자료가 없습니다."로 끝나고, 알림 버튼은 붉은 "알림 1건"입니다.
   - 확인: 주소창에 `http://127.0.0.1:4173/#/records/factory`를 치고 열면 표 자리에 노란 "현재 자료를 받지 못해 기록을 불러오지 못했습니다. 다시 조회하면 불러옵니다."가 보입니다.
   - `apiBaseUrl`을 원래 값(`API_CONTRACT.md` 9절 표의 1단계 주소)으로 되돌려 저장하고 새로고침하면 "조회 정상"으로 돌아옵니다.

## 3-18. 기준 시각 목록과 과거 시각 조회

```text
[3-18] 지난 시각의 운영 상태를 다시 보도록, 머리 부분의 기준 시각 목록을 "현재"와 오늘의 정시로 채우고 과거 시각을 고르면 그 시각 자료를 받는 기능을 추가해 주세요.
목록을 연 채로 조회가 와도 목록을 다시 만들지 않고, 과거 시각에서는 자동 조회와 남은 초를 멈추며 "현재"로 오면 다시 시작합니다.
시각을 바꾸면 이전 자료를 비우고 바로 조회하며, 시각이나 화면이 바뀌기 전에 보낸 요청의 응답은 버립니다. 과거 자료 안내는 다음 번호에서 만듭니다.
자세한 내용은 docs/guide/session-3.md의 "기준 시각 목록"과 "과거 시각 조회"를 참고해 주세요.
```
- 확인: 기준 시각 상자를 열면 "현재", "00:00", "01:00" … 지금까지의 정시가 보입니다. 목록을 연 채로 10초 조회가 지나가도 목록이 닫히거나 고르던 위치가 바뀌지 않습니다.
- 확인: "10:00"처럼 이른 정시를 고르면 남은 초 글자가 사라지고 그래프 막대가 줄고 수량이 작아집니다. 1분 넘게 기다려도 새 `snapshot` 줄이 생기지 않고, 새로고침 버튼을 누르면 `snapshot?at=…` 줄이 하나 생깁니다.

## 3-19. 과거 자료 안내와 "현재로 돌아가기"

```text
[3-19] 지금 과거 자료를 보고 있다는 것을 알도록, 과거 시각일 때 조회 정보 줄 뒤 칸에 고른 시각 안내와 밑줄 친 "현재로 돌아가기" 버튼을 추가해 주세요.

자세한 내용은 docs/guide/session-3.md의 "과거 시각 조회"를 참고해 주세요.
```
- 확인: 과거 시각에서 본문 위에 "… 10:00:00 기준 · 과거 자료"와 밑줄 친 "현재로 돌아가기"가 보입니다. 누르면 "현재 시각 기준"과 "다음 조회 10초"가 다시 보입니다.

## 3-20. 조회 기록 남기기

```text
[3-20] 이 탭이 보낸 조회를 되짚어 보도록, 조회 한 번마다 요청 시각, 결과, 응답시간을 담은 조회 기록을 남기고 이 탭에 최근 200건만 저장하는 기능을 추가해 주세요.
버린 응답도 한 건으로 남기고, 페이지를 떠나거나 새로고침하는 중에 끊긴 요청은 실패로 보지 않고 남기지도 않으며, 떠날 때 확인 창은 띄우지 않습니다.
조회 기록을 보여 주는 카드와 화면은 뒤 번호에서 만듭니다.
자세한 내용은 docs/guide/session-3.md의 "조회 기록"을 참고해 주세요.
```
- 확인: F12 Application 탭, 왼쪽 Session storage에서 `http://127.0.0.1:4173`을 누르면 `tumble-query-log` 줄이 있고 10초마다 값이 길어집니다. 새로고침할 때 "사이트를 새로고침하시겠습니까?" 같은 확인 창이 뜨지 않습니다.

## 3-21. 데이터 조회 기록 카드

```text
[3-21] 오늘 운영 화면에서 조회 결과를 바로 보도록, "공장 조회"·"창고 조회" 카드에 마지막 조회 시각, 결과, 응답시간을 추가해 주세요.
```

## 3-22. 조회 기록 화면: 맨 위 카드와 막대 줄

```text
[3-22] 조회 결과를 한눈에 보도록, 조회 기록 화면 맨 위 카드에 제목과 마지막 조회 결과, 조회 한 번마다 막대 하나를 오래된 것부터 놓는 막대 줄을 추가해 주세요.

```
- 확인: 오늘 운영의 "공장 조회" 카드에서 "전체보기"를 누르면 "생산 데이터 조회"와 "자료 제공"이 보이고, 초록 막대가 높이 64px 정도로 나란히 서서 10초마다 하나씩 늘어납니다.
- 확인: 막대에 마우스를 올리면 시각·결과·응답시간이 뜹니다.

## 3-23. 조회 기록 화면: 막대 아래 글과 조회 기록 표

```text
[3-23] 조회 결과를 자세히 보도록, 조회 기록 화면의 막대 줄 아래에 성공률 줄, 막대 색 설명, 고른 막대의 글을, 카드 아래에 최신 조회부터 그리는 조회 기록 표를 추가해 주세요.
```

- 확인: 막대 아래에 표가 보이고 맨 윗줄이 가장 최근 조회입니다. 생산 화면과 출고 화면의 요청 시각이 같습니다(공장·창고를 한 요청으로 조회하기 때문입니다).

## 3-24. 다시 그려도 위치와 고른 막대 지키기

```text
[3-24] 10초마다 다시 그려도 보던 곳을 잃지 않도록, 조회 기록 화면에 막대 줄과 표의 가로 스크롤 위치, 초점, 고른 막대의 글을 지키는 기능을 추가해 주세요.
화면 주소가 바뀐 뒤 처음 그릴 때는 지키지 않고 고른 막대도 잊습니다.
자세한 내용은 docs/guide/session-3.md의 "조회 기록 화면"을 참고해 주세요.
```
- 확인: 휴대폰 폭(375px)에서 막대 줄을 옆으로 밀어 두고 막대 하나를 누른 뒤 10초 조회가 지나가게 둡니다. 막대가 하나 늘어도 민 위치가 그대로이고, 아래 글은 고른 막대의 글 그대로입니다.
- 확인: Network 탭 속도를 "느린 4G"로 두고 머리 부분에 "조회 중…"이 보일 때 F5로 새로고침하기를 세 번 합니다. "제한 없음"으로 되돌린 뒤 조회 기록 표에 "실패" 줄이 새로 생기지 않았습니다(3-20).

## 3-25. 기록 화면 기준 시각과 끝 시각 검사

```text
[3-25] 과거 시각에서도 맞는 구간의 기록을 보도록, 기록 화면의 시작·종료 칸에 기준 시각 날짜의 00:00:00부터 기준 시각까지로 범위와 기본값을 맞추는 기능을 추가해 주세요.
기록이 없을 때 가짜 기록을 만들지 않습니다. 종료가 시작보다 이르면 종료 칸에 안내를 걸어 요청하지 않고, 같거나 늦어지면 바로 풉니다.
자세한 내용은 docs/guide/session-3.md의 "기록 화면"을 참고해 주세요.
```
- 확인: 기준 시각을 "10:00"으로 고르고 생산 기록 화면을 열면 종료 칸이 10:00:00이고, 표에는 그때까지의 기록만 보입니다.
- 확인: 시작 시각을 종료 시각보다 늦게 넣고 "시간대 조회"를 누르면 Network 탭에 새 `records` 줄이 생기지 않고 종료 칸에 "끝 시각은 시작 시각과 같거나 늦어야 합니다."가 뜹니다. 종료를 시작보다 늦게 고치면 바로 다시 누를 수 있습니다.

## 3회차 끝 확인

- [ ] 생산·출고 수량, 그래프, 상태가 강사 API 값과 같고, 사진 주소가 강사 API 주소입니다.
- [ ] Network 탭 "느린 4G"로 새로고침하면 화면 틀과 "조회 중"이 먼저 보이고, "0개"로 보이지 않습니다.
- [ ] "다음 조회 10초"부터 세고 조회하며, "마지막 조회 성공" 시각이 바뀝니다. 사진이 깜박이지 않습니다.
- [ ] 새로고침 버튼을 연달아 눌러도 `snapshot` 요청이 겹치지 않습니다.
- [ ] 정상 화면 뒤 "오프라인"이면 이전 숫자가 남고 "조회 실패", 안내 끝이 "아래 내용은 이전 조회 자료입니다."이고, 알림 맨 앞이 "최신 자료를 가져오지 못했습니다."입니다.
- [ ] 처음부터 실패하면 "조회 중" 없이 "확인 불가"·"대기"가 보이고, 안내가 연결 실패 문장으로 시작해 "조회할 자료가 없습니다."로 끝납니다.
- [ ] 기록 HTTP 400 문장은 3-14에서 본 것으로 합니다.
- [ ] 과거 시각에서는 남은 초와 자동 조회가 멈추고, "현재로 돌아가기"로 돌아옵니다.
- [ ] 기준 시각 목록을 연 채로 10초 조회가 지나도 목록이 닫히거나 위치가 바뀌지 않습니다.
- [ ] 기록 화면에 실제 기록이 보이고 "시간대 조회"가 동작합니다. 다른 화면에 갔다 오면 칸이 기본값이고, 같은 기록이면 10초 조회 뒤에도 표의 위치와 초점이 남고, 기준 시각까지의 기록만 보입니다.
- [ ] 시작이 종료보다 늦으면 요청 없이 종료 칸에 "끝 시각은 시작 시각과 같거나 늦어야 합니다."가 뜹니다.
- [ ] 조회 기록이 요청 한 번에 한 건 남고, 새로고침 뒤에도 남습니다. 조회 중 새로고침은 실패로 남지 않습니다.
- [ ] 조회 기록 화면에 색 막대, 성공률, 최신순 표가 보이고, 10초 조회 뒤에도 고른 막대의 글·막대 줄 위치가 남습니다.
- [ ] 파일 탐색기나 AI 도구의 파일 목록에 `public\sample-data.js`가 없습니다.
