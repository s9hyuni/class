# 3회차: 강사 API 연결과 과거 조회

- **시작 상태**: 2회차를 끝낸 `C:\ai-class\tumble-dashboard`에서 이어 합니다. 화면의 숫자·그래프·기록 표가 예시 자료(`public\sample-data.js`)로 채워지고, 주소별 화면, 알림 목록, 도움말이 동작합니다. 2회차를 못 끝냈으면 회차 공통 안내대로 `milestone-2` 브랜치를 받습니다.
- **끝나면 되는 것**
  - 화면이 강사 API의 실제 값으로 채워지고 10초마다 다시 조회합니다. 새로고침 버튼으로 바로 조회할 수도 있습니다.
  - 조회가 실패해도 이전 값이 남고, 왜 실패했는지 노란 안내로 알려 줍니다.
  - 헤더에서 과거 시각을 골라 그때의 자료를 보고, 조회 기록 화면에서 이 탭이 보낸 요청을 막대와 표로 봅니다.
  - `public\sample-data.js`가 없어집니다.
- **준비물**: Chrome, 인터넷, 서버를 켜 둔 터미널(이하 "서버 창"), 프로젝트 맨 위의 `API_CONTRACT.md`

## 시작 전에 (프롬프트 없이 직접 합니다)

1. 서버 창에서 `npm.cmd start`로 서버를 켜고 Chrome에서 `http://127.0.0.1:4173`을 엽니다. 2회차 끝 확인표가 맞는 상태에서 시작합니다.
2. `API_CONTRACT.md` 1절에서 강사 API 주소를 찾습니다. Chrome 새 탭 주소창에 그 주소 뒤로 `/api/v1/snapshot`을 붙여 엽니다. JSON 글자가 보이면 됩니다. 화면 위의 "보기 좋게 표시"를 켜면 읽기 쉽습니다.
3. 그 화면에서 `sites` 아래 `factory`의 `completed`와 `target` 값을 찾아 적어 둡니다. 3-6에서 화면 숫자와 대조합니다.

## 진행 방법

- 프롬프트를 번호 순서대로 하나씩 붙여 넣습니다. 이번 회차는 화면 파일(`public` 폴더)만 고치므로 서버는 켜 둔 채로 두고, 단계가 끝날 때마다 브라우저만 새로고침(F5)합니다.
- 요청은 F12(개발자 도구)의 Network 탭에서 봅니다. 새로고침한 뒤 목록에 `snapshot`, `records` 같은 줄이 생기고, 줄을 누르면 요청 주소와 상태(200 등)가 보입니다.
- Network 탭 위쪽의 속도 메뉴("제한 없음")에서 "느린 4G"(영문 화면은 Slow 4G)나 "오프라인"을 고를 수 있습니다. 확인이 끝나면 늘 "제한 없음"으로 되돌립니다.
- 강사 API의 상황은 강사가 바꿉니다. 수강생은 읽기만 합니다.
- 화면의 색과 배치는 예시와 조금 달라도 됩니다. 따옴표로 적은 문구와 각 단계의 "확인"에 적힌 동작은 같아야 합니다.

### 실패 상황 만드는 법 (3-17, 3-31 ~ 3-40에서 씁니다)

`public\config.js`(3-2에서 만듭니다)를 Antigravity 편집기에서 직접 고치고 저장한 뒤 새로고침합니다. 바꾸기 전 값을 적어 두고, 확인한 뒤 꼭 되돌립니다.

| 만들 실패 | 방법 |
|---|---|
| 정상 화면을 본 뒤의 실패 | Network 탭 속도 메뉴에서 "오프라인"을 고르고 헤더의 새로고침 버튼을 누릅니다 |
| 연결 실패(처음부터) | `apiBaseUrl` 값을 `"http://127.0.0.1:3999"`로 바꾸고 새로고침 |
| HTTP 404 | `apiBaseUrl` 값의 강사 API 주소 끝에 `/abc`를 붙이고 새로고침 |
| 시간 초과 | `timeoutMs` 값을 `100`으로 바꾸고 새로고침 |

`config.js`는 페이지를 열 때 한 번 읽습니다. 그래서 `config.js`를 바꾼 시험은 늘 "처음부터 실패한 화면"이 됩니다.

## 3-15. 새로고침 버튼 1: 조회 겹치지 않게


## 3-51. 떠나는 중에 끊긴 요청은 빼기

```text
페이지를 떠나는 중에 끊긴 요청은 조회 실패가 아닙니다. window의 beforeunload와 pagehide에서 "떠나는 중" 표시를 켜고, setTimeout으로 timeoutMs 뒤에 끕니다. pageshow에서도 끕니다.
beforeunload에서는 확인 창이 뜨지 않도록 preventDefault와 returnValue를 쓰지 않습니다. Chrome은 새로고침할 때 진행 중인 요청을 pagehide보다 먼저 실패로 돌려주므로 beforeunload에서 켜야 합니다.
떠나는 중에 실패한 조회는 오류 문구로 쓰지 않고 조회 기록에도 남기지 않습니다. 떠나는 중이라도 성공한 조회는 남깁니다.
```
- 확인: 새로고침할 때 "사이트를 새로고침하시겠습니까?" 같은 확인 창이 뜨지 않습니다. 실패가 남지 않는지는 3-59 뒤에 확인합니다.

## 3-52. 데이터 조회 기록 카드

```text
오늘 운영의 "데이터 조회 기록" 두 카드에 마지막 기록을 써 주세요. #factory-query는 "2026. 11. 04. 13:10:05 · 조회 성공"(실패면 "조회 실패")입니다.
#factory-query-meta는 보이게 하고 "응답시간: 230ms · " 뒤에 "현장 값 제공"(값이 없으면 "현장 값 누락", 실패면 "자료를 받지 못했습니다.")을 붙입니다.
창고 카드(#warehouse-query, #warehouse-query-meta)는 available.warehouse를 봅니다. 기록이 없으면 "조회 기록 없음"이고 meta는 숨깁니다.
```
- 확인: 오늘 운영 아래쪽 "공장 조회", "창고 조회" 카드에 10초마다 새 시각과 응답시간이 보입니다. 새 탭에서 같은 주소를 열면 그 탭은 "조회 기록 없음"에서 시작합니다(탭마다 따로 남습니다).

## 3-58. 다시 그려도 스크롤 위치 지키기


## 3-59. 고른 막대 기억하기

```text
막대마다 data-at에 그 기록의 requestedAt을 넣고, 막대를 누르거나 초점이 가면 그 값을 "고른 기록"으로 기억해 주세요. 고른 기록은 화면 주소가 바뀔 때(hashchange) 지웁니다.
다시 그릴 때 고른 기록의 막대가 있으면 .history-detail을 처음 안내 대신 그 막대의 title 글자로 둡니다.
같은 화면이고 다시 그리기 전에 초점이 막대에 있었으면, 다시 그린 뒤 data-at이 같은 막대에 focus({ preventScroll: true })로 초점을 되돌립니다.
```
- 확인: 막대 하나를 누르고 10초 조회가 지나가도 아래 글은 고른 막대의 글 그대로입니다. Tab으로 막대에 초점을 둔 채 조회가 지나가도 초점 테두리가 같은 막대에 남고, Enter를 누르면 그 막대의 글이 나옵니다.
- 확인: "← 오늘 운영"으로 갔다가 "전체보기"로 다시 들어오면 아래 글이 처음 안내로 돌아갑니다.
- 확인(3-51): Network 탭 속도를 "느린 4G"로 두고 헤더가 "조회 중…"일 때 F5로 새로고침하기를 세 번 합니다. "제한 없음"으로 되돌린 뒤 이 화면 표에 "실패" 줄이 새로 생기지 않았습니다.

## 3-60. 기록 화면을 기준 시각에 맞추기

```text
기록 화면의 시작·종료 칸을 기준 시각에 맞춰 주세요. min은 기준 시각 날짜의 00:00:00, max는 기준 시각(한국 시간, 초까지)이고, 고친 적이 없으면 기본값도 그 둘입니다.
기준 시각은 마지막 snapshot의 viewTime, 자료가 없으면(시각을 막 바꿨거나 첫 응답 전) 고른 과거 시각, 그것도 없으면 브라우저 시계의 지금입니다.
서버가 기준 시각 뒤의 접수·처리 시각을 null로 보내므로 그 기록은 지금처럼 "접수 대기"·"처리 대기"로 보입니다. 기록이 없을 때 수량 0인 가짜 기록을 만들지 않습니다.
```
- 확인: 기준 시각을 "10:00"으로 고르고 생산 기록 화면을 열면 종료 칸이 10:00:00이고, 표에는 그때까지의 기록만 보입니다. 종료 칸을 기준 시각보다 늦게 고르려 하면 입력 칸이 막거나 "시간대 조회" 때 브라우저 안내가 뜹니다.

## 3-61. 끝 시각이 시작보다 이르면 막기

```text
종료가 시작보다 이르면 기록 요청을 보내지 마세요. 종료 칸(#record-to)에 setCustomValidity("끝 시각은 시작 시각과 같거나 늦어야 합니다.")를 걸고, "시간대 조회"를 누를 때 양식의 reportValidity()로 브라우저 안내를 보입니다.
시작과 종료가 같으면 허용합니다. 비었거나 형식이 틀린 값은 이 검사에서 막지 않고 required·min·max 검사에 맡깁니다.
이 검사는 "시간대 조회"를 누를 때, 두 칸의 input 이벤트, 조회 뒤 칸을 다시 채울 때마다 해서 칸을 고치면 안내가 바로 풀리게 합니다.
```
- 확인: 시작 시각을 종료 시각보다 늦게 넣고 "시간대 조회"를 누르면 Network 탭에 새 `records` 줄이 생기지 않고 종료 칸에 "끝 시각은 시작 시각과 같거나 늦어야 합니다."가 뜹니다. 종료를 시작보다 늦게 고치면 바로 다시 누를 수 있고, 시작과 종료를 같게 두면 조회됩니다.
- 확인: 강사가 공장 지연 상황(`factory-delay`)으로 바꾼 뒤 현재 생산 기록 화면을 보면 마지막 줄이 "10개", 서버 접수 "접수 대기", 서버 처리 "처리 대기", 상태 "접수 대기"입니다. 강사 안내에 맞춰 확인합니다.
